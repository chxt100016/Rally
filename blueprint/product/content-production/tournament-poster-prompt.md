## 一句话价值

为内容人员交付匹配赛事特征的海报创作提示词。

## 核心概念

- 职业赛事  从公开数据源采集的 ATP/WTA 赛事，用于赛程、比分和内容展示，不接受本产品用户报名。
- 赛事海报提示词  根据职业赛事的名称、级别、场地和城市特征整理的图片创作文字要求，不是最终赛事图片。

## 业务对象

### 赛事海报提示词

| 业务名称 | 描述 | 取值说明 |
|---|---|---|
| 赛事编号 | 指明需要生成提示词的职业赛事。 | — |
| 赛事名称 | 用于海报主题和标题的赛事名称。 | — |
| 所属巡回赛 | 赛事所属的职业巡回赛。 | ATP、WTA、ITF 或大满贯赛事。 |
| 赛事级别 | 决定海报的球场视角和构图方式。 | 二百五十级、五百级、一千级、大满贯或年终总决赛。 |
| 场地类型 | 决定海报中的球场材质与环境表现。 | 硬地、红土、草地、室内硬地或室内红土。 |
| 举办城市 | 用于海报标题或远景中的城市特征。 | — |
| 提示词正文 | 可直接交给图片创作者或生图工具的文字要求。 | 三维卡通版本或通用赛事背景图版本。 |

## 状态机

无

## 主流程

触发方式（并列）：HTTP（内容赛事海报入口）、HTTP（赛事提示词入口）；终态：返回指定职业赛事的一段海报创作提示词。

1. 内容人员指定一个赛事编号发起生成。
2. 取得该职业赛事的名称、巡回赛、级别、场地类型和举办城市。
3. 从内容赛事海报入口触发时，生成 `App Store` 风格的 3D 卡通海报描述，并按赛事级别补充视角、光线、观众规模及城市或中央球场特色。
4. 从赛事提示词入口触发时，生成通用赛事背景图规则，列出赛事名称、级别、场地类型、可用的城市信息及建议拍摄角度。
5. 将完整提示词正文直接交付给内容人员，不改变职业赛事资料。

## 分支与异常

| 什么情况 | 怎么处理 | 对外提示 | 做了一半的怎么收场 |
|---|---|---|---|
| 内容赛事海报入口未找到赛事 | 停止生成 | 赛事不存在 | 没有业务数据变更 |
| 赛事提示词入口未找到赛事 | 不生成提示词 | 返回空结果 | 没有业务数据变更 |
| 3D 卡通版本遇到未识别的 `category` | 仍生成基础提示词，不补充级别对应的视角、光线、观众规模和特色 | 返回降级后的提示词 | 没有业务数据变更 |
| 3D 卡通版本遇到未识别的 `surface` | 仍生成提示词，不补充场地材质描述 | 返回降级后的提示词 | 没有业务数据变更 |
| 3D 卡通版本未命中赛事特色 | 1000 及以上赛事改用通用中央球场特征；250、500 级赛事在有城市时改用通用城市气质 | 返回使用通用特色的提示词 | 没有业务数据变更 |
| 通用版本遇到未识别的 `category` | 保留原级别文字，并采用中角度俯视球场 | 返回使用默认角度的提示词 | 没有业务数据变更 |
| 通用版本遇到未识别的 `surface` | 保留原场地类型文字 | 返回包含原场地文字的提示词 | 没有业务数据变更 |
| 通用版本没有城市 | 省略城市行 | 返回不含城市信息的提示词 | 没有业务数据变更 |

## 业务边界

本服务负责根据已有职业赛事资料交付一段海报创作提示词，止于提示词返回；不负责生成、上传、存储或绑定赛事图片，也不修改、翻译或补全赛事资料。

## 遗留与待定

- 两个触发入口使用不同模板：一个要求 3D 卡通、无人球场和留白排版，另一个要求赛事背景图且强调避免赛事名称图标；哪套规则是标准版本、是否应继续并存，需要内容负责人确定。
- 两套模板、级别对应的视角与氛围、场地描述均写死在现有规则中，调整机制和维护责任人待定。
- 城市或中央球场特色按一组写死的赛事编号匹配，素材覆盖范围、验收标准和增补流程待内容负责人确定。
- 3D 卡通版本会把赛事名称、固定文字 `tennis open`、巡回赛和级别拼接成标题，重复、语言混排和空值处理规则待内容负责人确定。
- `category` 与 `surface` 在数据库中不是受约束枚举，两种模板对未知值的降级方式不同，允许值及统一降级规则待定。
- `surface` 的数据库长度为 `VARCHAR(10)`，但现有规则识别的 `indoor clay` 超过该长度；该取值能否实际保存及应如何兼容待定。
- 职业赛事以 `tournament_id` 和 `year` 共同保证唯一，但本服务只按 `tournament_id` 取一条记录；同一编号跨年份时应选择哪一届待定。
- 250、500 级赛事已命中特色素材但 `city` 为空时，提示词仍会生成缺少城市名的城市特色语句；预期处理方式待定。
