## 一句话价值

为运营手工录入一个高德抓不到的球场，直接对用户可用。

## 核心概念

- 球场  可供网球活动选择的线下场地，包含位置、环境和联系资料。
- 手工录入球场  由运营在后台逐条填写而不是从高德抓取得到的球场，来源记为系统录入，没有三方来源编号。
- 球场业务编号  球场在平台内的唯一标识，新增时生成，之后不再变更。

## 交付内容

类型: 新增类

成功后形成此前不存在的业务事实，并交付主流程所述标识或结果；初始状态、后续可变更范围和可见范围，以本节下列规则、业务对象及业务边界为准。

## 主流程

触发源：运营在后台发起 HTTP 新增；终态：一条新球场已写入球场库，并交付球场业务编号。

1. 接收球场资料。
2. 在城市名录中确认城市编码存在，取得城市名称；填了区域编码时在区县名录中取得区域名称。
3. 生成球场业务编号。
4. 把别名列表与标签列表分别以英文逗号连接，把评分、费用、开放时间、联系电话，以及球场名称的拼音与拼音首字母整理为扩展资料。
5. 写入球场，来源记为系统录入，三方来源编号留空，约球次数记为 0，状态取指令中的状态或默认为可用。
6. 交付新增球场的业务编号。

## 分支与异常

| 什么情况 | 怎么处理 | 对外提示 | 做了一半的怎么收场 |
|---|---|---|---|
| 球场名称为空或只含空白字符 | 拒绝新增 | `name: 请填写球场名称` | 未修改任何业务数据。 |
| 城市编码为空或只含空白字符 | 拒绝新增 | `cityCode: 请选择城市` | 未修改任何业务数据。 |
| 城市编码在城市名录中不存在 | 拒绝新增 | `城市不存在` | 未修改任何业务数据。 |
| 区域编码在区县名录中不存在 | 拒绝新增 | `区域不存在` | 未修改任何业务数据。 |
| 球场环境、场地材质或球场状态不是允许的取值 | 拒绝新增 | `参数不正确` | 未修改任何业务数据。 |
| 经度或纬度超出取值范围 | 拒绝新增 | `参数不正确` | 未修改任何业务数据。 |
| 名称、别名、地址、备注或标签超出长度上限 | 拒绝新增 | `参数不正确` | 未修改任何业务数据。 |
| 球场库写入失败 | 新增失败 | `系统异常，请稍后重试` | 未修改任何业务数据。 |

## 业务边界

本服务负责按运营填写的资料新增一条手工录入球场，到交付球场业务编号为止。服务只对运营开放，不面向普通用户。服务不负责查重，不负责从高德补全球场资料，不负责球场的编辑与停用，不负责球场审核。

## 遗留与待定

| 等级 | 待定的是什么 | 要谁来定 |
|---|---|---|
| P2 | 新增时不做重名或就近查重，同一处球场可以被反复录入；是否需要按名称或坐标查重，应由产品与运营确认。 | 产品与场地运营负责人 |
| P1 | 手工录入球场的 `source_id` 为空，后续抓取不会把它与高德的同一处球场关联起来，可能出现重复球场；两者怎么归并，应由产品与运营确认。 | 产品与场地运营负责人 |
| P1 | 新增时球场状态默认为 `ACTIVE`，即录即对用户可见，未经过 `COLLECTED` 待审核环节；手工录入是否需要审核，应由产品与运营确认。 | 产品与场地运营负责人 |
| P2 | 球场名称的拼音与拼音首字母由系统按名称生成，多音字场景的正确性无法保证，也没有提供人工修正入口；是否需要允许运营手工填写拼音，应由产品确认。 | 产品与场地运营负责人 |
| P2 | `alias` 与 `tags` 按英文逗号连接后写入，未定义单项内容本身含逗号时的规则，应由产品与场地数据负责人确认。 | 产品与场地运营负责人 |
| P2 | 新增球场没有记录操作人和操作时间，无法追溯是谁录入的；是否需要操作留痕，应由产品与运营确认。 | 产品与场地运营负责人 |
