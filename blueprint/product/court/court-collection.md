## 一句话价值

为运营按城市从高德地图抓取网球场并写入球场库，交付本次收录统计。

## 核心概念

- 高德地图  提供网球场兴趣点数据的外部地图服务，通过关键词搜索接口按行政区划检索。
- 兴趣点  高德地图返回的一条场所记录，含名称、地址、经纬度、行政区划、评分、营业时间等资料，是收录球场的原始素材。
- 三方来源编号  兴趣点在高德地图中的唯一标识，写入 `rally_court.source_id`，用于判断一个球场是否已收录。
- 全量覆盖模式  已收录的球场按本次抓取结果改写，未收录的新增。
- 增量模式  只新增未收录的球场，已收录的球场一概不改。
- 区县  城市下的行政区划。高德关键词搜索单次可取的结果有上限，因此按区县逐个检索再汇总。
- 就近合并  同一处场馆在高德常被拆成多条兴趣点，把彼此距离很近的兴趣点并成一个球场。

## 业务对象

### 抓取指令

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `cityCode` | 字符串 | 是 | 要抓取的城市编码，取自平台城市名录的六位城市编码。 |
| `mode` | 枚举 | 是 | 抓取模式，取值 `FULL` 或 `INCREMENT`。 |

`mode` 的取值：

| 取值 | 业务含义 |
|---|---|
| `FULL` | 全量覆盖：已收录的球场按本次抓取结果改写，未收录的新增。 |
| `INCREMENT` | 增量：只新增未收录的球场，已收录的一概不改。 |

### 城市与区县名录

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | 字符串 | 是 | 城市或区县的六位编码。城市名录来自 `city.json`，区县名录来自 `district.json`。 |
| `name` | 字符串 | 是 | 城市或区县中文名称。 |

城市与区县的归属按编码推导，规则如下：

| 情况 | 归属规则 |
|---|---|
| 直辖市（城市编码为 `110000`、`120000`、`310000`、`500000`） | 区县编码前 2 位与城市编码前 2 位相同 |
| 其他城市 | 区县编码前 4 位与城市编码前 4 位相同 |
| 名录中查不到任何区县的城市 | 不按区县拆分，直接按城市编码检索 |

### 兴趣点

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | 字符串 | 是 | 高德兴趣点编号，收录为球场的三方来源编号。 |
| `name` | 字符串 | 是 | 场所名称。 |
| `address` | 字符串 | 否 | 场所地址。 |
| `location` | 字符串 | 否 | 经纬度，格式为 `经度,纬度`。 |
| `citycode` | 字符串 | 否 | 高德返回的城市编码，本服务不采用，以指令中的城市编码为准。 |
| `cityname` | 字符串 | 否 | 高德返回的城市名称，本服务不采用，以城市名录中的名称为准。 |
| `adcode` | 字符串 | 否 | 区县编码，收录为球场的区域编码。 |
| `adname` | 字符串 | 否 | 区县名称，收录为球场的区域名称。 |
| `type` | 字符串 | 否 | 高德场所类型串，参与球场环境判定。 |
| `business.rectag` | 字符串 | 否 | 高德推荐标签，参与有效性校验与球场环境判定。 |
| `business.keytag` | 字符串 | 否 | 高德关键标签，参与有效性校验与球场环境判定。 |
| `business.rating` | 字符串 | 否 | 评分。 |
| `business.cost` | 字符串 | 否 | 人均消费。 |
| `business.opentime_week` | 字符串 | 否 | 一周营业时间。 |
| `business.tel` | 字符串 | 否 | 联系电话。 |

### 球场（`rally_court`）

本服务写入的字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `biz_id` | `VARCHAR(32)` | 是 | 球场业务编号，新增时生成，已收录球场沿用原值。 |
| `source_id` | `VARCHAR(128)` | 是 | 三方来源编号，取兴趣点的 `id`，在球场库内唯一。 |
| `name` | `VARCHAR(128)` | 是 | 球场名称，取主记录兴趣点的名称。 |
| `alias` | `VARCHAR(128)` | 否 | 就近合并时被并掉的兴趣点名称，以英文逗号连接；没有被并掉的兴趣点时为空。 |
| `address` | `VARCHAR(256)` | 否 | 球场地址。 |
| `lng` | `DOUBLE` | 否 | 球场经度。 |
| `lat` | `DOUBLE` | 否 | 球场纬度。 |
| `city_code` | `VARCHAR(32)` | 是 | 城市编码，取抓取指令中的城市编码。 |
| `district_code` | `VARCHAR(32)` | 否 | 区域编码，取兴趣点的 `adcode`。 |
| `city_name` | `VARCHAR(64)` | 否 | 城市名称，取城市名录中该城市编码对应的名称。 |
| `district_name` | `VARCHAR(64)` | 否 | 区域名称，取兴趣点的 `adname`。 |
| `type` | `VARCHAR(32)` | 否 | 球场环境，按判定规则得出；判不出时为空。 |
| `tags` | `VARCHAR(512)` | 否 | 球场标签，以英文逗号连接；没有标签时为空。 |
| `ext_data` | `TEXT` | 否 | 球场扩展资料，含 `rating`、`cost`、`opentime`、`tel`、`pinyin`、`pinyinInitial`；单项资料缺失时不写入该项。 |
| `source` | `VARCHAR(32)` | 是 | 来源，固定为 `SYSTEM`。 |
| `status` | `VARCHAR(32)` | 是 | 状态，固定为 `ACTIVE`。 |

本服务不写入 `surface`、`remark`、`meetup_count`。

### 有效性校验规则

一条兴趣点满足以下任一条件即被丢弃，不收录：

| 条件 | 说明 |
|---|---|
| 名称或地址含 `学练馆`、`穿线`、`培训中心` | 非标准可打球场地。 |
| `business.rectag` 与 `business.keytag` 拼接后不含 `网球场` | 不是网球场。 |

### 球场环境判定规则

取兴趣点的名称、地址、场所类型串、`rectag`、`keytag` 拼成一段文字，按顺序判定，命中即止：

| 顺序 | 条件 | 结果 |
|---|---|---|
| 1 | 该段文字含 `室内` | `INDOOR` |
| 2 | 该段文字含 `楼顶`、`天台`、`屋顶`、`露台` 之一 | `OUTDOOR` |
| 3 | 地址中出现 3 层及以上楼层（形如 `3F`、`3楼`、`3层`，数字为 3 到 9） | `OUTDOOR` |
| 4 | 该段文字含 `公园`、`广场`、`体育场` 之一 | `OUTDOOR` |
| 5 | 以上都不命中 | 为空 |

### 球场标签生成规则

按下表逐条判定，命中即加上对应标签，标签之间不去重顺序不变：

| 标签 | 判定条件 |
|---|---|
| `空调` | 名称或地址含 `空调` |
| `楼顶` | 名称或地址含 `楼顶`、`天台`、`屋顶`、`露台` 之一 |
| `草地` | 名称含 `草地` |
| `红土` | 名称含 `红土` |
| `硬地` | 名称含 `硬地` 或 `硬场` |
| `近地铁` | 名称或地址含 `地铁`，或地址含 `站` |
| `停车方便` | 名称或地址含 `停车`，或名称含 `parking`（不区分大小写） |
| `公共设施` | 名称含 `公园`、`体育中心`、`体育公园` 之一 |
| `高评分` | 评分不为空且不小于 4.6 |
| `24小时营业` | 一周营业时间含 `24小时` 或 `00:00-24:00` |
| `有灯光` | 名称或地址含 `灯光` 或 `夜间` |
| `室内场` | 球场环境判定为 `INDOOR` |
| `室外场` | 球场环境判定为 `OUTDOOR` |

### 就近合并规则

| 项 | 规则 |
|---|---|
| 合并范围 | 同一次城市抓取内通过有效性校验的全部兴趣点。 |
| 合并判据 | 两点球面距离不超过 100 米即视为同一场馆；相互可达的兴趣点归为一簇。 |
| 主记录 | 簇内评分最高的一条；评分为空视为最低。 |
| 被并掉的 | 簇内其余兴趣点，名称写入主记录球场的 `alias`，本身不单独收录。 |
| 经纬度缺失 | 不参与合并，各自成簇。 |

### 收录结果

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `cityCode` | 字符串 | 是 | 本次抓取的城市编码。 |
| `cityName` | 字符串 | 是 | 本次抓取的城市名称。 |
| `mode` | 枚举 | 是 | 本次采用的抓取模式。 |
| `districtCount` | 整数 | 是 | 本次实际检索的区县数量；未按区县拆分时为 0。 |
| `fetchedCount` | 整数 | 是 | 从高德取回的兴趣点总条数。 |
| `filteredCount` | 整数 | 是 | 被有效性校验丢弃与被就近合并并掉的兴趣点条数。 |
| `validCount` | 整数 | 是 | 解析出的球场条数。 |
| `insertedCount` | 整数 | 是 | 本次新增的球场条数。 |
| `updatedCount` | 整数 | 是 | 本次改写的球场条数；增量模式下固定为 0。 |
| `skippedCount` | 整数 | 是 | 因已收录而跳过的球场条数；全量覆盖模式下固定为 0。 |
| `failedDistricts` | 字符串列表 | 是 | 抓取失败的区县编码；全部成功时为空列表。 |

## 状态机

无

## 主流程

触发源：运营在后台发起 HTTP 抓取；终态：本次抓取的球场已写入球场库，并交付收录统计。

1. 接收城市编码与抓取模式。
2. 在城市名录中确认该城市编码存在，取得城市名称。
3. 在区县名录中按编码推导规则取得该城市下的全部区县；一个区县都取不到时，改为按城市编码整体检索。
4. 逐个区县向高德按关键词 `网球场` 检索，一页取完取下一页，直到某一页取不到兴趣点为止；相邻两次检索之间留出间隔以避开高德的调用频率限制。
5. 汇总全部区县取回的兴趣点，逐条做有效性校验，丢弃不是网球场和非标准场地的条目。
6. 对通过校验的兴趣点做就近合并，每簇留下一条主记录，其余兴趣点的名称记作主记录的别名。
7. 逐条把主记录解析成球场：判定球场环境、生成球场标签、拆出经纬度、取城市与区县归属，并把评分、人均消费、营业时间、联系电话以及球场名称的拼音与拼音首字母整理为扩展资料。
8. 按抓取模式写入球场库：全量覆盖模式下，三方来源编号已存在的球场按本次结果改写，不存在的新增；增量模式下，三方来源编号已存在的球场跳过，只新增不存在的。新增的球场生成球场业务编号，来源记为系统录入，状态记为可用。
9. 交付本次的检索区县数、取回条数、丢弃条数、有效条数、新增条数、改写条数、跳过条数和抓取失败的区县清单。

## 分支与异常

| 什么情况 | 怎么处理 | 对外提示 | 做了一半的怎么收场 |
|---|---|---|---|
| 城市编码为空或只含空白字符 | 拒绝抓取 | `cityCode: 请选择城市` | 未修改任何业务数据。 |
| 抓取模式为空或不是 `FULL`、`INCREMENT` 之一 | 拒绝抓取 | `mode: 抓取模式不正确` | 未修改任何业务数据。 |
| 城市编码在城市名录中不存在 | 拒绝抓取 | `城市不存在` | 未修改任何业务数据。 |
| 某个区县向高德检索失败或高德返回错误 | 跳过该区县，继续抓取其余区县，把该区县编码记入抓取失败清单 | 无，失败区县在收录结果中列出 | 已抓到的其余区县照常写入。 |
| 某个区县检索不到任何兴趣点 | 视为该区县没有球场，继续抓取其余区县 | 无 | 不影响其余区县。 |
| 兴趣点经纬度缺失或无法解析 | 该兴趣点不参与就近合并，经纬度按空写入 | 无 | 该球场其余资料照常写入。 |
| 兴趣点评分无法识别为数字 | 视为没有评分，不加 `高评分` 标签，就近合并时按最低评分处理 | 无 | 该球场其余资料照常写入。 |
| 单条球场写入失败 | 跳过该条，继续写入其余球场 | 无 | 已写入的球场保留，失败的不计入新增或改写条数。 |
| 球场库读写失败 | 抓取失败 | `系统异常，请稍后重试` | 失败前已写入的球场保留。 |

## 业务边界

本服务负责按城市编码从高德地图抓取网球场兴趣点，完成有效性校验、就近合并、球场环境与标签解析，并按全量覆盖或增量模式写入球场库，到交付收录统计为止。服务只对运营开放，不面向普通用户。服务不负责判断城市是否已开通业务，不负责球场的人工审核，不负责判定场地材质，不负责删除高德已下线但库中仍在的球场，不负责单个球场的新增、编辑与停用。

## 遗留与待定

- 抓取写入的球场状态固定为 `ACTIVE`，会直接出现在用户端球场清单中，跳过了球场表设计中的 `COLLECTED` 待审核环节；抓取结果是否需要人工审核后才可用，应由产品与运营确认。
- 全量覆盖模式只改写高德能提供的字段，运营在球场编辑中手工填写的 `remark`、`surface` 不受影响；`name`、`address`、`tags` 等被运营改过的字段会被抓取结果覆盖，是否应保护人工修改，应由产品与运营确认。
- 高德已下线、迁址或改名的球场在库中会成为陈旧数据，全量覆盖模式下也不会被停用；库中有而本次抓取没有的球场怎么处理，应由产品与运营确认。
- `district.json` 的行政区划数据偏旧，杭州仍含已撤销的下城区、江干区，且缺临平区、钱塘区，会导致部分区域抓不到球场；区县名录的更新责任与更新频率，应由产品与运营确认。
- 高德关键词固定为 `网球场`，无法抓取羽毛球、匹克球等其他场地；是否需要支持按运动项目抓取，应由产品确认。
- 单次抓取的耗时随城市区县数量增长，接口需同步等待抓取结束；可接受的最长等待时长以及超时后怎么处理，应由产品与运营确认。
- 就近合并的 100 米阈值、`高评分` 标签的 4.6 分线来自现有抓取脚本，缺少业务依据；是否需要按城市或场馆密度调整，应由产品确认。
- `alias` 字段长度为 128 字符，一簇内被并掉的兴趣点较多时可能装不下；超长时怎么取舍，应由产品与场地数据负责人确认。
- 高德地图的调用凭据、调用配额上限与超配额后的处理方式未定义，应由技术与运营确认。
