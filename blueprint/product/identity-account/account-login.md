## 一句话价值

为微信小程序访问者建立或识别账户并交付登录身份。

## 核心概念

- 账户  用户获得访问身份的载体，可关联登录凭据、手机号和个人资料。

## 业务对象

### 账户

| 业务名称 | 描述 | 取值说明 |
|---|---|---|
| 账户编号 | 唯一标识登录账户。 | — |
| 用户编号 | 标识账户所归属的用户。 | — |
| 登录渠道 | 区分账户采用的身份识别方式；本服务识别微信小程序账户。 | 微信小程序：使用微信小程序身份登录；手机号：使用手机号登录，本服务不创建或识别该渠道。 |
| 微信身份标识 | 微信小程序范围内唯一识别用户的身份。 | — |
| 微信跨应用标识 | 微信返回时保存，用于跨微信应用识别同一用户；未返回时为空。 | — |

### 用户资料

| 业务名称 | 描述 | 取值说明 |
|---|---|---|
| 用户编号 | 唯一标识首次登录时建立的用户资料。 | — |
| 昵称 | 首次登录时使用默认昵称“球员”。 | — |
| 头像 | 首次登录时使用默认头像。 | — |
| 性别 | 首次登录时使用未公开。 | 男性：用户性别为男性；女性：用户性别为女性；未公开：用户未公开性别，也是首次登录的默认值。 |

### 登录结果

| 业务名称 | 描述 | 取值说明 |
|---|---|---|
| 登录凭证 | 代表本次已识别登录身份的限时凭证。 | — |
| 用户编号 | 已识别账户所关联的用户编号。 | — |
| 是否新用户 | 表示本次是否新建账户与用户资料。 | 是：本次首次建立账户和用户；否：识别到已有账户。 |
| 是否需要完善资料 | 表示用户是否需要继续完善注册资料；当前与是否新用户保持一致。 | 是：需要完善资料；否：无需进入新用户资料完善流程。 |

## 交付内容

类型: 执行类

消费者当场取得主流程所述的外部处理效果与成功结果；重复发起、下游失败和已完成结果的处理，以本节下列规则及分支与异常为准。

## 主流程

触发源：微信小程序用户发起登录；终态：交付已识别用户的登录凭证、用户编号、新用户标识和资料完善标识。

1. 接收访问者提供的微信临时登录凭据，并确认其不为空。
2. 由微信核实临时登录凭据，取得该访问者的 `openid`，以及微信可能返回的 `unionid`。
3. 按 `wechat_miniapp` 与 `openid` 识别已有账户。
4. 若账户已存在，沿用账户关联的用户编号，并将本次标记为非新用户。
5. 若账户不存在，建立使用默认昵称和默认头像的用户资料，再建立与该用户资料关联的微信小程序账户，并将本次标记为新用户。
6. 为已识别的用户编号签发登录凭证，交付登录结果；是否需要完善资料与是否新用户保持相同。

## 分支与异常

| 什么情况 | 怎么处理 | 对外提示 | 做了一半的怎么收场 |
|---|---|---|---|
| 微信临时登录凭据为空 | 拒绝登录，不核实微信身份 | `code 不能为空` | 尚未建立或修改账户与用户资料。 |
| 微信登录配置缺失 | 终止微信身份核实 | `微信配置错误` | 尚未建立或修改账户与用户资料。 |
| 微信未返回有效结果、返回失败码或缺少 `openid` | 拒绝登录 | `微信 code 无效: {微信返回原因}` | 尚未建立或修改账户与用户资料。 |
| 调用微信时发生未被业务规则归类的异常 | 登录失败并向外传递异常 | 没有统一的业务提示 | 尚未建立或修改账户与用户资料。 |
| 识别已有账户时读取失败 | 登录失败并向外传递异常 | 没有统一的业务提示 | 尚未建立或修改账户与用户资料。 |
| 首次登录时用户资料建立失败 | 登录失败并向外传递异常 | 没有统一的业务提示 | 未建立账户。 |
| 首次登录已建立用户资料，但账户建立失败或相同微信身份已被绑定 | 登录失败并向外传递异常 | 没有统一的业务提示 | 已建立的用户资料没有明确撤销或后续认领规则。 |
| 登录凭证无法签发 | 登录失败并向外传递异常 | 没有统一的业务提示 | 已有账户保持不变；首次登录已建立的用户资料与账户没有明确撤销规则。 |

## 业务边界

本服务负责核实微信小程序临时登录凭据、识别或首次建立账户与基础用户资料，并交付登录身份。服务到登录结果交付为止，不负责手机号绑定、注册资料完善、个人档案引导与完善，也不负责登录后的业务权限判断、凭证续期或退出登录。

## 遗留与待定

| 等级 | 待定的是什么 | 要谁来定 |
|---|---|---|
| P2 | “是否需要完善资料”当前直接等于“是否新用户”，没有核对已有用户的实际资料完整度；应由产品确认该标识的业务判定规则。 | 产品与账号安全负责人 |
| P1 | 首次登录先建立用户资料、再建立账户；后一步失败时，已建立的用户资料没有撤销、保留或重新关联规则，应由产品与业务负责人确定收场方式。 | 产品与账号安全负责人 |
| P2 | 已有账户登录时只沿用其关联的 `user_id`，没有核对对应 `user` 是否仍存在；数据不一致时是否允许交付登录身份，应由产品与业务负责人确定。 | 产品与账号安全负责人 |
| P1 | 登录凭证的有效期限取自运行配置，未见固定业务期限；具体期限及到期后的续期方式应由产品确认。 | 产品与账号安全负责人 |
| P1 | 微信身份核实、账户读写和登录凭证签发的非预期失败没有统一对外提示，应由产品确定用户可理解的失败口径。 | 产品与账号安全负责人 |
