## 一句话价值

向运营人员交付全部已登记配置及当前版本。

## 核心概念

- 已登记配置  平台明确列入配置名录的配置项，不等于数据库中任意一条配置记录。
- 配置覆盖  已启用的全局保存值取代内置默认值；没有保存值或保存值停用时仍采用默认值。
- 配置版本  某个全局保存记录的变更序号；尚无保存记录时为 0。

## 业务对象

### 配置项

| 业务名称 | 描述 | 取值说明 |
|---|---|---|
| 配置标识 | 唯一标识一项已登记的平台配置；本服务交付全部已登记配置。 | 包括用户等级与评分、约球规则、评价规则、用户素材限制、支付规则、赛事规则、城市、公共素材及首页内容配置。 |
| 配置说明 | 配置在登记名录中的中文业务说明。 | — |
| 当前值 | 当前对业务生效的配置内容；已启用的运营设置优先，否则采用内置默认值。 | — |
| 默认值 | 平台为该配置预置的初始内容。 | — |
| 配置版本 | 标识当前运营设置的版本；从未设置时为零。 | — |
| 覆盖状态 | 表示当前值是否来自运营设置。 | 已覆盖：采用已启用的运营设置；未覆盖：采用内置默认值。 |

## 交付内容

类型: 查询类

向消费者交付当前业务事实的查询结果；身份与状态造成的展示差异，以及列表的排序、分页和无结果口径，以本节下列规则及主流程、分支与异常为准。

## 主流程

触发源：HTTP（运营）；终态：配置名录中全部已登记配置的当前全量视图已交付，不改变配置状态。

1. 核验调用方具有运营访问权限。
2. 按配置名录逐项取得对应的 `global` 保存记录。
3. 对每项配置，存在已启用保存记录时采用保存值；记录不存在或停用时采用内置默认值。
4. 按登记顺序交付每项配置的标识、登记说明、当前值、默认值、保存版本和覆盖状态。

## 分支与异常

| 什么情况 | 怎么处理 | 对外提示 | 做了一半的怎么收场 |
|---|---|---|---|
| 未提供有效的运营访问凭据，或运营访问凭据未配置 | 拒绝查询 | `无权限访问` | 本服务只读，没有业务对象需要恢复。 |
| 某项没有 `global` 保存记录 | 交付该项内置默认值、版本 `0` 和覆盖状态 `false` | 查询成功 | 本服务只读，无需收场。 |
| 某项 `global` 保存记录已停用 | 交付该项内置默认值、保存记录现有版本和覆盖状态 `false` | 查询成功 | 本服务只读，无需收场。 |
| 某项已启用的保存值与登记用途不相符或无法按预期解析 | 仍原样交付保存值，不在查询时校验或回退 | 查询成功 | 本服务不修复、停用或覆盖该配置。 |
| 配置资料读取失败 | 终止查询 | `系统异常，请稍后重试` | 本服务只读，没有业务对象需要恢复。 |

## 业务边界

本服务只向具有运营访问权限的调用方交付配置名录中全部已登记配置的当前值、内置默认值、保存版本和覆盖状态；交付数量随名录版本动态变化。它不查询或交付未登记的数据库配置，不修改、启停或校验配置，不负责配置在各业务中的实际解释与使用，也不提供配置变更历史。

## 遗留与待定

| 等级 | 待定的是什么 | 要谁来定 |
|---|---|---|
| P2 | 数据库初始化资料包含 `review.tag.max_length`、`review.tag.max_custom_per_review`、`review.score.games4_max`、`review.score.games6_max`、`review.score.tiebreak_min`、`review.score.tiebreak_lead` 六项启用记录，但它们没有进入当前配置名录，因此本服务不会交付；这些配置是否应登记或移除，需产品与技术负责人确认。 | 产品与平台运营负责人 |
| P2 | `score.max` 的登记说明与其标识及用途不一致，当前说明为“用户注册初始校准度”；正确业务定义需产品确认。 | 产品与平台运营负责人 |
| P2 | `user.hint.video` 和 `user.hint.ntrp` 的登记说明为空，运营后台无法从说明辨识用途；说明文案需产品确认。 | 产品与平台运营负责人 |
| P2 | 当前配置名录及内置默认值随产品发布改变，却没有独立的名录版本、生效时间和变更记录；是否需要可审计的配置基线，需产品与运营确认。 | 产品与平台运营负责人 |
| P1 | 运营访问凭据只表达是否允许访问，没有关联具体运营人员或角色；是否需要分权及查询审计，需安全和运营负责人确认。 | 产品与平台运营负责人 |
