## 一句话价值

为可复盘约球新增一盘唯一比分。

## 核心概念

- 约球  围绕一次明确时间、场地、人数和参与条件组织的网球活动，不只是两人邀约。
- 约球报名  用户与约球之间的参与关系，可处于待审批、已加入、已拒绝、已撤回、已退出、已评价或已跳过。
- 赛后复盘  约球结束后记录比分、评价同场用户或明确跳过评价的阶段。
- 有效参与者  约球发布者，或报名处于已加入、已评价、已跳过的人。
- 一盘比分  同一约球中由盘号标识的一条比赛结果，包含比赛类型、盘制、两侧阵容和得分。
- 盘制  一盘比分的计分方式，分为按局计分和抢分计分。

## 业务对象

### 比分记录

| 业务名称 | 描述 | 取值说明 |
|---|---|---|
| 比分编号 | 唯一标识本次新增的一盘比分。 | — |
| 所属约球 | 本盘比分对应的约球。 | — |
| 盘号 | 本盘在该约球全部比分中的顺序，同一约球内不可重复。 | — |
| 比赛类型 | 表示本盘采用单打或双打阵容。 | 单打：每侧一名球员；双打：每侧两名球员。 |
| 盘制 | 表示本盘采用的计分方式。 | 常规局：按局数记录得分；抢分局：按抢分分数记录得分。 |
| 双方阵容 | 记录两侧参与本盘比赛的球员及其展示资料。 | — |
| 双方得分 | 记录两侧在本盘取得的分数。 | — |
| 获胜方 | 根据双方得分确定的本盘胜方。 | 甲方：甲方得分更高；乙方：乙方得分更高。 |

## 状态机

无。比分记录没有业务状态字段，新增后即作为一盘有效比分参与后续查询。

## 主流程

触发源：约球发布者或符合当前资格的报名用户通过 HTTP 提交；终态：目标约球新增一盘唯一比分。

1. 识别当前用户，取得目标约球及其全部报名关系。
2. 确认当前用户是约球发布者，或报名状态为 `PENDING`、`JOINED`、`REVIEWED`、`SKIPPED`。
3. 确认约球实际处于进行中或已结束，且尚未超过复盘截止时刻。
4. 确认该约球下尚不存在相同盘号的比分。
5. 接收本盘的比赛类型、盘制、双方球员位置、主分和可选抢七分。
6. 比较 A、B 两侧主分，将分数较高的一侧记为本盘胜方。
7. 记录约球开始时间，并补齐各球员当时的昵称、头像和性别快照。
8. 建立本盘比分，记下提交人，并返回成功标识。

## 分支与异常

| 什么情况 | 怎么处理 | 对外提示 | 做了一半的怎么收场 |
|---|---|---|---|
| 没有登录凭证 | 拒绝新增 | 登录已过期，请重新登录 | 不建立比分记录。 |
| 登录凭证无效 | 拒绝新增 | 登录凭证无效，请重新登录 | 不建立比分记录。 |
| `meetupId` 为空或只有空白 | 拒绝新增 | 约球ID不能为空 | 不建立比分记录。 |
| `setNum` 为空 | 拒绝新增 | 盘号不能为空 | 不建立比分记录。 |
| `setFormatType` 为空 | 拒绝新增 | 赛制不能为空 | 不建立比分记录。 |
| `matchType` 为空 | 拒绝新增 | 比赛类型不能为空 | 不建立比分记录。 |
| `sideAPlayer1` 为空或只有空白 | 拒绝新增 | A侧选手1不能为空 | 不建立比分记录。 |
| `sideBPlayer1` 为空或只有空白 | 拒绝新增 | B侧选手1不能为空 | 不建立比分记录。 |
| `sideAScore` 为空 | 拒绝新增 | A侧比分不能为空 | 不建立比分记录。 |
| `sideBScore` 为空 | 拒绝新增 | B侧比分不能为空 | 不建立比分记录。 |
| 目标约球不存在 | 拒绝新增 | 约球不存在 | 不建立比分记录。 |
| 当前用户不是发布者，且没有 `PENDING`、`JOINED`、`REVIEWED` 或 `SKIPPED` 报名 | 拒绝新增 | 你未报名该约球 | 不建立比分记录。 |
| 约球实际状态不是进行中或已结束 | 拒绝新增 | 约球不可评价 | 不建立比分记录。 |
| 当前时刻晚于约球结束时间加复盘期限 | 拒绝新增 | 评价已超期 | 不建立比分记录。 |
| 同一约球已经存在相同 `set_number` | 拒绝新增 | 盘号重复 | 保留原比分，不建立重复记录。 |
| A、B 两侧主分相同 | 无法确定胜方，拒绝新增 | 获胜边无效 | 不建立比分记录；已读取的资料不产生业务变更。 |
| 提交无法识别的比赛类型或盘制 | 请求无法受理 | 系统异常，请稍后重试 | 不建立比分记录。 |
| 同场同盘在并发提交中发生唯一性冲突 | 仅保留先成功的一条 | 系统异常，请稍后重试 | 不建立后到的重复记录。 |
| 比分保存失败 | 新增失败 | 系统异常，请稍后重试 | 不建立比分记录，也不改变约球或报名。 |

## 业务边界

- 本服务从约球发布者或符合当前资格的报名用户提交一盘比分开始，到同场同盘唯一的比分记录建立并返回成功标识为止。
- 本服务允许约球处于进行中或已结束；是否可复盘同时受约球结束时间和 `review.deadline_days` 限制。
- 本服务按提交的盘号保证同一约球下一盘一条；不同比赛类型、阵容或记录人也不能复用相同盘号。
- 本服务只按 A、B 两侧主分大小决定 `win_side`，抢七分不参与胜方判断。
- 本服务保存提交时的球员昵称、头像和性别快照；球员日后修改档案不会回写既有比分。
- 本服务不修改约球及报名状态，不把记录人标为已评价，也不完成赛后复盘。
- 比分修改和比分删除分别由独立服务负责；本服务不覆盖已有盘号。
- 本服务不返回新比分的 `biz_id` 或完整内容，调用方需通过比分查询取得结果。
- 本服务当前不推进个人评分、战绩核查期或其他统计结果。

## 遗留与待定

- `setNum` 仅要求不为空，没有校验必须从 1 开始、连续递增或限制总盘数；盘号规则应由产品负责人确定。
- `SINGLE`、`DOUBLE`、`RALLY` 只作为记录值保存，没有约束单打每侧一人、双打每侧两人或拉球的阵容结构；三类比赛的阵容规则应由赛事与产品负责人确定。
- 当前不核对比分 `match_type` 与约球 `match_type`；一场约球能否混记单打、双打、拉球应由产品负责人确定。
- 当前不校验提交球员是否为该约球的有效参与者，也不禁止同一用户占据多个位置或同时出现在两侧；合法阵容和代记范围应由产品负责人确定。
- 记录人只需是约球发布者，或报名状态为 `PENDING`、`JOINED`、`REVIEWED`、`SKIPPED`，不要求出现在本盘阵容中；是否允许代记他人比分应由产品负责人确定。
- 待审批报名当前可以新增比分，但尚未成为有效参与者；待审批用户是否应具备赛后记录权限需由产品负责人确定。
- `GAME` 和 `TIEBREAK` 没有各自的合法分数范围、获胜门槛、领先差或封顶规则；盘制计分规则应由赛事与产品负责人确定。
- `sideAScore`、`sideBScore` 没有非负与上限校验，只要不相等即可计算胜方；合法主分范围应由产品负责人确定。
- 抢七分字段没有成对填写、非负、最低分和领先分校验，也不限制只在特定盘制或局分下填写；抢七适用和计分规则应由赛事与产品负责人确定。
- 字段说明称局分 6:6 时填写抢七分，但主分相等会在抢七分参与判断前被拒绝；局分与抢七分如何共同确定胜方应由赛事与产品负责人确定。
- 不存在的球员编号不会阻止新增，只会缺少昵称、头像和性别快照；球员身份有效性规则应由产品负责人确定。
- 新增成功只返回成功标识，不返回比分编号，调用方无法从本次结果直接定位新记录；返回内容应由产品负责人确定。
- 新增比分后的评分重算尚未实现；比分应在何时、按何规则影响个人评分、战绩核查期和统计应由产品与评分负责人确定。
- 同场同盘的并发冲突不会返回“盘号重复”，而会落入通用系统异常；并发场景的对外提示应由产品负责人确定。
