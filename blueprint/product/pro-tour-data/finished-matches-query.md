## 一句话价值

为用户按赛事交付种子状态与分轮完赛结果

## 核心概念

- 职业赛事  从公开数据源采集的 ATP/WTA 赛事，用于赛程、比分和内容展示，不接受本产品用户报名。
- 种子  职业赛事中用于体现重点球员及签表排序的编号。
- 完赛比赛  状态为已结束、可交付胜方与逐盘比分的职业比赛。
- 完赛轮次  将完赛比赛按决赛、半决赛、各级淘汰轮次归拢后的展示分组。

## 状态机

无。本服务查阅已有职业赛事数据，不改变职业比赛、签表、参赛信息或球员的业务状态。

## 主流程

触发源：HTTP（用户/匿名）；终态：所选职业赛事的种子状态与分轮完赛结果已交付。

1. 用户提交一个或多个职业赛事标识，确定本次查阅范围。
2. 汇总这些赛事各签表中种子号非空且不为 `0` 的球员，补充展示姓名、国家或地区与所属巡回赛。
3. 根据所查赛事的全部已结束比赛判断种子是否落败；未落败种子按 ATP、WTA 分组，已落败种子归入 `OUT` 并展示落败轮次，各组内按种子号升序排列。
4. 取得所查赛事中状态为 `FINISHED` 的比赛，排除对阵双方均未确定的记录，并补充双方展示姓名、国家或地区和种子号。
5. 为每场完赛比赛交付轮次、日期、时间、场地、双方球员、逐盘比分、胜方与比赛时长；逐盘比分同时形成盘数和最后一盘局分摘要。
6. 将比赛按轮次归组，依次展示决赛、半决赛、8 强、16 强、32 强、64 强、96 强和 128 强；同轮比赛按实际开始时间倒序排列，缺少实际开始时间的排在最后。
7. 球员姓名和球场名称有简体中文译文时交付译文，没有译文时保留原文并登记为待译内容；轮次与已结束状态直接交付中文名称。
8. 向用户同时交付种子分组与完赛轮次分组；没有符合条件的数据时对应部分为空列表。

## 分支与异常

| 什么情况 | 怎么处理 | 对外提示 | 做了一半的怎么收场 |
|---|---|---|---|
| 未提供赛事标识参数 | 拒绝发起查询 | 返回参数缺失，具体文案由统一入口规则决定 | 不改变职业赛事数据 |
| 所给赛事标识均没有种子和完赛比赛 | 返回空的种子分组与比赛分组 | 查询成功，结果为空 | 不改变职业赛事数据 |
| 多个赛事标识中只有部分有数据 | 交付有数据赛事的合并结果 | 查询成功 | 无数据赛事不产生占位分组 |
| 比赛状态不是精确的 `FINISHED` | 不纳入完赛比赛，也不用于种子淘汰判断 | 无 | 原数据保持不变 |
| 一场完赛比赛的对阵双方都为空 | 从交付结果中排除 | 无 | 原比赛保持不变 |
| 一场完赛比赛只确定一方球员 | 保留比赛，另一方球员信息为空 | 查询成功 | 其余比赛正常交付 |
| 比赛球员在球员资料中不存在 | 以外部球员标识作为比赛中的展示姓名，国家或地区为空 | 查询成功 | 其余已补齐资料照常交付 |
| 种子球员在球员资料中不存在 | 保留种子号和外部球员标识，姓名、国家或地区为空 | 查询成功 | 其余种子照常交付 |
| 国家或地区三字码无法识别 | 原码同时作为代码和名称交付，旗帜代码为空 | 查询成功 | 其余球员资料照常交付 |
| 球员姓名或球场名称没有简体中文译文 | 保留原文并登记待译内容 | 查询成功 | 已有译文仍正常交付 |
| 轮次值不在已知轮次范围内 | 保留原轮次值，轮次中文名为空，并排在已知轮次之后 | 查询成功 | 其余轮次正常交付 |
| `sets_json` 为空 | 交付空的逐盘比分，盘数和最后一盘局分为空 | 查询成功 | 其余比赛信息正常交付 |
| `sets_json` 不是可识别的逐盘比分 | 无法形成完赛结果，本次查询中断 | 返回查询失败，具体文案未在本调用链定义 | 不改变职业赛事数据；本次不交付部分结果 |

## 业务边界

- 负责按一个或多个职业赛事标识交付种子分组和完赛轮次分组。
- 负责以已有完赛比赛判断种子的在赛或淘汰状态，并展示淘汰轮次。
- 负责交付完赛比赛的双方球员、种子号、国家或地区、胜方、逐盘比分、时间、场地和时长。
- 负责使用已有简体中文译文展示球员姓名与球场名称；缺少译文时只登记待译内容，不负责生成译文。
- 不负责采集或刷新职业赛事、签表、球员、种子和比赛数据。
- 不负责交付未结束比赛；待赛比赛由“待赛比赛查询”负责。
- 不负责按年份、签表类型或轮次筛选，也不提供分页。

## 遗留与待定

- 查询条件只有 `tournament_id`，没有年份；同一赛事标识存在多个年份时会合并各年份的签表、种子与完赛比赛，是否符合届次查阅口径需职业赛事数据负责人确认。
- 多赛事一起查询时，种子淘汰记录只按 `player_id` 归并，没有同时区分 `tournament_id`；球员在一项赛事落败可能令另一项赛事中的同一球员也显示为已淘汰，需职业赛事数据负责人确定隔离口径。
- 球员资料读取只按 `player_id` 匹配，没有同时区分 `tour`；ATP 与 WTA 出现相同外部球员标识时采用哪份资料没有规则，需职业赛事数据负责人确认。
- 未淘汰种子只明确识别 `ATP`，其他所有 `tour` 值都会归入 `WTA`；职业赛事支持范围及未知巡回赛的分组规则需职业赛事数据负责人确认。
- 已淘汰种子统一进入 `OUT`，不再保留 ATP/WTA 分组；用户是否需要在淘汰组内区分巡回赛需产品确认。
- 种子是否淘汰由任一已结束比赛中的落败记录直接决定，没有校验胜方是否确属对阵双方；异常赛果的种子状态处置需职业赛事数据负责人确认。
- 赛事标识没有格式、数量上限与存在性校验，也不会提示哪些赛事不存在；输入规则和部分命中提示需产品确认。
- 完赛轮次固定按决赛到 128 强排列，与通常从早轮到决赛的时间顺序相反；该展示顺序需产品确认。
- 已结束比赛只按 `started_at` 倒序，实际开始时间相同或为空时没有稳定的次级排序；稳定展示规则需产品确认。
- 比赛只有一方球员时仍作为完赛比赛交付，`winner_id` 为空或不属于对阵双方时也不拦截；完赛数据有效性标准需职业赛事数据负责人确认。
- `sets_json` 的每盘字段都允许为空，最后一盘任一方局数为空时不形成局分摘要；残缺比分是否应继续展示需产品确认。
- 轮次、比赛状态与时长展示文案由固定规则形成，但代码没有说明这些中文文案是否需要纳入统一翻译管理，需内容负责人确认。
