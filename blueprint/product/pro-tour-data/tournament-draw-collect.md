## 一句话价值

为运营更新职业赛事签表、对阵和参赛球员。

## 核心概念

- 职业赛事  从公开数据源采集的 ATP/WTA 赛事，用于赛程、比分和内容展示，不接受本产品用户报名。
- 签表  职业赛事的参赛位置、轮次结构和潜在晋级路径。
- 种子  职业赛事中用于体现重点球员及签表排序的编号。

## 交付内容

类型: 批处理类

一次处理主流程界定的一批业务对象；处理范围、成功失败统计、部分成功口径与失败对象的收场方式，以本节下列规则及分支与异常为准。

无。签表、球员和签表参赛信息没有由本服务控制的业务状态流转；职业比赛的 `COMING`、`PENDING`、`LIVE`、`FINISHED` 是外部状态快照，采集时按新快照刷新，不校验状态转移方向。

## 主流程

触发源：HTTP（运营，指定职业赛事）、HTTP（运营，当前职业赛事）、定时任务（DRAW 阶段，每 60 分钟）；终态：目标赛事的签表、比赛快照、球员和参赛信息已更新。

1. 指定赛事的触发根据外部赛事标识取得一项已收录赛事；当前赛事与 DRAW 定时触发取得开始日不晚于明日、结束日不早于昨日的全部赛事。
2. 根据 `ATP`/`WTA` 与是否为 `GS` 选择外部数据源：非大满贯 ATP 取自 `api.tennistv.com`，大满贯 ATP 取自 `app.atptour.com`，非大满贯 WTA 取自 `wta-webapi-prod-apimanagement.azure-api.net`，大满贯 WTA 取自 `app.atptour.com`；WTA 同时从 `app.atptour.com` 补充已完成比赛快照。
3. 将来源数据按单打签表拆出轮次、对阵、球员、种子和入围方式，非单打内容不进入当前交付。
4. 只处理本地已收录的职业赛事；以赛事标识、年份和签表类型建立新签表，或刷新已有签表的人数与轮数。
5. 将签表中的比赛关联到对应签表，新增尚未收录的比赛，并用外部新快照中已提供的对阵、轮次、状态、胜方与比分等内容刷新已有比赛；新快照缺失的内容不清空旧值。
6. 以外部球员标识和巡回赛更新球员姓名与国家或地区，再以签表和球员更新种子号及入围方式。
7. 当前赛事与定时触发逐项完成全部目标赛事；单项赛事失败不阻止其余赛事继续更新。

## 分支与异常

| 什么情况 | 怎么处理 | 对外提示 | 做了一半的怎么收场 |
|---|---|---|---|
| 当前采集范围内没有赛事 | 正常结束，不采集任何签表 | 当前签表采集完成 | 无变更 |
| 指定的外部赛事标识未收录 | 无法取得赛事的年份、巡回赛与类别，采集失败 | 系统异常，请稍后重试 | 无变更 |
| `tour` 不是 `ATP` 或 `WTA`，或 `category` 为空 | 无法选择数据源，该赛事采集失败 | 指定赛事 HTTP 触发返回系统异常；当前赛事 HTTP 触发仍返回“当前签表采集完成”；定时触发无业务提示 | 已完成的其他赛事保留更新 |
| 外部数据源请求失败、返回空数据或没有可识别单打签表 | 该来源不产生更新 | HTTP 当前赛事触发仍返回“当前签表采集完成”，其他触发无业务提示 | 已有数据保持原状 |
| 外部数据所属赛事未在本地收录 | 跳过该签表 | 无 | 该签表不产生变更 |
| 已完成比赛补充数据的赛事标识或年份与本次目标不一致 | 拒绝该份补充数据 | 无 | 先前已完成的 WTA 签表更新保留 |
| 一场比赛缺少赛事标识、年份或外部比赛标识 | 拒绝保存该批比赛，该签表采集失败 | 指定赛事 HTTP 触发返回系统异常；当前赛事 HTTP 触发仍返回“当前签表采集完成”；定时触发无业务提示 | 签表人数和轮数可能已刷新，该签表的球员与参赛信息未更新 |
| 比赛、球员或参赛信息保存失败 | 该签表采集失败 | 指定赛事 HTTP 触发返回系统异常；当前赛事 HTTP 触发仍返回“当前签表采集完成”；定时触发无业务提示 | 当次失败之前已更新的签表、比赛或球员保留，后续对象不再更新 |

## 业务边界

- 本服务负责把已收录的指定或当前职业赛事刷新为可查阅的单打签表，并同步交付签表内的对阵、轮次、球员、种子与入围方式。
- 本服务依赖职业赛事名录已存在，不负责新增或修改赛事名录。
- 本服务会把签表来源携带的比赛状态、胜方和比分作为快照一并更新，并为 WTA 补充已完成比赛；不承诺完整赛程、实时赛况或最终赛果，这些分别由后续采集服务承担。
- 本服务不负责职业赛事查询、球员排名采集、内容生产或图片维护。
