## 一句话价值

向用户汇总本人胜负、胜率与当前连续战绩。

## 核心概念

- 个人档案  用户基础资料与网球资料的组合，包含 NTRP、自评状态、评分和展示视频。
- 约球  围绕一次明确时间、场地、人数和参与条件组织的网球活动，不只是两人邀约。
- 赛后复盘  约球结束后记录比分、评价同场用户或明确跳过评价的阶段。

## 业务对象

### 我的战绩统计

| 业务名称 | 描述 | 取值说明 |
|---|---|---|
| 对局形式 | 限定需要统计的比分记录；未指定时统计全部。 | 单打：只统计单打比分；双打：只统计双打比分；拉球：只统计拉球比分。 |
| 总盘数 | 纳入统计的比分记录总数；当前每条记录代表一盘。 | — |
| 胜盘数 | 本人所在一侧获胜的比分记录数。 | — |
| 负盘数 | 总盘数减去胜盘数。 | — |
| 胜率 | 胜盘数占总盘数的百分比，保留一位小数；无记录时展示“--”。 | — |
| 连续战绩 | 从最新记录开始连续胜利或连续失利的类型及盘数；无记录时为空。 | 连胜：最新连续战绩均为胜利；连负：最新连续战绩均为失利。 |

## 交付内容

类型: 查询类

向消费者交付当前业务事实的查询结果；身份与状态造成的展示差异，以及列表的排序、分页和无结果口径，以本节下列规则及主流程、分支与异常为准。

## 主流程

触发源：接口（用户）；终态：交付本人当前战绩统计，不改变任何业务对象状态。

1. 依据当前登录身份确定需要统计的用户本人。
2. 取得本人作为 A、B 任一侧选手出现的全部比分记录，并按业务唯一标识倒序排列。
3. 若用户指定参与方式，只保留该单打、双打或拉球类型的比分记录；未指定时保留全部记录。
4. 逐条判断本人所在侧是否为获胜侧，分别累计胜数，并以记录总数减去胜数得到负数。
5. 以胜数除以记录总数形成保留一位小数的胜率；没有记录时以 `--` 表示胜率。
6. 从最新记录开始，连续累计与最新一盘胜负结果相同的记录，形成当前连胜或连负类型及次数；没有记录时两项均为空。
7. 向本人交付记录总数、胜数、负数、胜率与当前连续战绩。

## 分支与异常

| 什么情况 | 怎么处理 | 对外提示 | 做了一半的怎么收场 |
|---|---|---|---|
| 未携带登录凭证，或登录凭证没有使用约定格式 | 不受理统计 | 登录已过期，请重新登录 | 本服务只读，没有业务对象需要恢复 |
| 登录凭证无法验证 | 不受理统计 | 登录凭证无效，请重新登录 | 本服务只读，没有业务对象需要恢复 |
| `matchType` 不是 `SINGLE`、`DOUBLE`、`RALLY` 之一 | 不受理统计 | 参数类型错误 | 本服务只读，没有业务对象需要恢复 |
| 本人没有比分记录，或指定参与方式下没有记录 | 交付总数、胜数、负数均为 `0`，胜率为 `--`，连续战绩类型和次数为空 | 查询成功 | 本服务只读，没有业务对象需要恢复 |
| 有效登录身份没有对应账户或个人档案，也没有对应比分记录 | 不校验账户或个人档案是否存在，按无比分记录交付空统计 | 查询成功 | 本服务只读，没有业务对象需要恢复 |
| 比分记录的 `win_side` 不是本人所在侧 | 将该条记录计为负 | 查询成功 | 本服务只读，没有业务对象需要恢复 |
| 持久化的 `match_type` 无法识别为约定枚举 | 终止统计 | 系统异常，请稍后重试 | 本服务只读，没有业务对象需要恢复 |
| 比分记录读取失败，或发生其他未归类错误 | 终止统计 | 系统异常，请稍后重试 | 本服务只读，没有业务对象需要恢复 |

## 业务边界

- 本服务从已登录用户查询本人战绩开始，到交付当次统计结果为止，全程不修改业务对象状态。
- 本服务只统计当前登录用户本人，不接受指定其他用户，也不交付逐盘比分明细；逐盘明细属于“我的比分查询”。
- 本服务读取本人出现在任一选手位置的全部 `rally_meetup_score` 记录，不核验关联约球当前状态、赛后复盘状态或记录时间范围。
- 本服务按每条盘级比分记录统计总数、胜负和连续战绩，不按约球合并为场级结果。
- 本服务只读取已经保存的比分，不负责新增、修改或删除比分，也不根据双方分数重新判定获胜侧。
- 本服务不把统计结果写入个人档案，不据此修改 NTRP、信誉分、可信度、校准度或其他个人资料。

## 遗留与待定

| 等级 | 待定的是什么 | 要谁来定 |
|---|---|---|
| P2 | `total`、胜负和连续战绩当前都按一盘比分记录计算，同一约球的多盘会分别计数；“战绩”应按盘还是按整场约球统计，需要产品负责人确定。 | 产品与用户运营负责人 |
| P2 | 最新记录当前按 `biz_id` 倒序认定，没有使用 `meetup_date`、`create_time` 或约球实际结束时间；连续战绩的正式时间顺序需要产品负责人确定。 | 产品与用户运营负责人 |
| P2 | 胜率固定保留一位小数、无记录显示 `--`，且数值不带百分号；展示精度、空值表达和单位需要产品负责人确定。 | 产品与用户运营负责人 |
| P1 | `win_side` 只在代码逻辑中识别 `A`、`B`，数据库没有枚举约束；其他非空值不会报错，而会被计为本人失败，异常数据的处理规则需要产品与数据负责人确定。 | 产品与用户运营负责人 |
| P1 | 若本人同时出现在比分记录的 A、B 两侧，当前优先按 A 侧判断胜负；选手位置的数据完整性规则和异常处理需要产品与数据负责人确定。 | 产品与用户运营负责人 |
| P1 | 当前不校验登录身份是否仍存在对应账户或个人档案；无对应资料且无比分记录时仍会交付空统计，是否允许需要产品负责人确定。 | 产品与用户运营负责人 |
| P1 | 当前统计不核验关联约球是否已结束、是否可复盘，也不限制比分日期；纳入战绩的约球状态和时间范围需要产品负责人确定。 | 产品与用户运营负责人 |
