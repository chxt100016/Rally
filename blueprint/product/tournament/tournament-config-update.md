## 一句话价值

让运营更新赛事配置，同时保留赛事状态与运营进度。

## 核心概念

- 自办赛事  由业务方配置规则、接受报名、组织匹配并推进比赛的竞赛活动。
- 资格赛  自办赛事进入正赛前的筛选阶段，胜者可能先进入待支付。
- 正赛  自办赛事锁定席位后的淘汰阶段，胜者按轮次继续晋级。

## 交付内容

类型: 变更类

成功后按主流程改写或撤销既有业务事实；允许变更的内容、前置状态、对外可见结果与原值留痕，以本节下列规则、业务对象及分支与异常为准。

无。本次修改不改变赛事的 `DRAFT`、`ACTIVE` 或 `ABANDONED` 状态，也不推进当前轮次。

## 主流程

触发源：HTTP（运营）；终态：赛事配置已更新，赛事状态与运营进度保持不变。

1. 运营指定一个已有自办赛事，并提交一份完整的可修改配置。
2. 确认赛事存在，校验必填项、字段格式、长度和非负限制。
3. 确认正赛签位数为 2 至 64 范围内的 2 次方，线下承接轮次小于正赛签位数。
4. 确认报名与资格赛时间满足既定先后关系。
5. 更新赛事名称、展示素材、主题、参赛条件、赛制、费用、时间和拒赛规则。
6. 保留赛事状态、当前轮次、已锁定席位数、结束时间和线下赛活动关联，并确认修改完成。

## 分支与异常

| 什么情况 | 怎么处理 | 对外提示 | 做了一半的怎么收场 |
|---|---|---|---|
| 未指定赛事，或指定赛事不存在 | 拒绝修改 | 赛事 ID 不能为空，或赛事不存在 | 赛事保持原配置 |
| 必填配置缺失，名称或规则描述超长，主题颜色或奖金格式不合法 | 拒绝修改 | 返回对应字段的校验提示 | 赛事保持原配置 |
| 正赛签位数不是 2 至 64 范围内的 2 次方 | 拒绝修改 | 正赛签位数只能是 2 到 64 的 2 次方 | 赛事保持原配置 |
| 线下承接轮次对应签位数不小于正赛签位数 | 拒绝修改 | 转线下轮次必须小于正赛签位数 | 赛事保持原配置 |
| 资格赛每组人数少于 2，报名费或任一拒赛次数上限为负 | 拒绝修改 | 返回对应数值限制提示 | 赛事保持原配置 |
| 报名开始时间不早于资格赛开始时间 | 拒绝修改 | 报名开始时间必须早于资格赛开始时间 | 赛事保持原配置 |
| 报名截止时间早于报名开始时间 | 拒绝修改 | 报名截止时间不能早于报名开始时间 | 赛事保持原配置 |
| 资格赛截止时间早于资格赛开始时间 | 拒绝修改 | 资格赛截止时间不能早于资格赛开始时间 | 赛事保持原配置 |

## 业务边界

本服务负责校验并更新一个已有自办赛事的配置，交付的是保留原状态与运营进度的最新赛事配置。它不负责创建、激活或废弃赛事，不调整已有报名、比赛、支付单或线下赛活动，也不重新执行匹配。

## 遗留与待定

| 等级 | 待定的是什么 | 要谁来定 |
|---|---|---|
| P1 | 当前允许修改 `ACTIVE` 和 `ABANDONED` 赛事，哪些状态应开放配置修改需要产品确认。 | 产品与赛事运营负责人 |
| P2 | `city_code` 可被更新，但 `city_name` 始终保留旧值；城市编码与名称如何同步需要产品与数据负责人确认。 | 产品与赛事运营负责人 |
| P2 | 比赛类型允许 `RALLY`，但赛事表定义只说明 `SINGLE`、`DOUBLE`；赛事是否支持拉球需要产品确认。 | 产品与赛事运营负责人 |
| P2 | 线下承接轮次允许全部赛事轮次，而赛事表定义只举出 `ROUND_4`、`ROUND_8`、`ROUND_16`；实际允许范围需要产品确认。 | 产品与赛事运营负责人 |
| P2 | `qualifier_group_size` 仅限制至少 2 人，而赛事表定义只说明默认 2 人、可设 3 人；是否需要上限需要产品确认。 | 产品与赛事运营负责人 |
| P2 | 可选配置传空值时，当前保存行为会保留旧值；是否应支持清空海报、主题、截止时间、奖金和规则描述需要产品确认。 | 产品与赛事运营负责人 |
| P1 | `ntrp_level` 只要求非空，没有数值格式或可选范围校验；赛事允许哪些 NTRP 等级需要产品确认。 | 产品与赛事运营负责人 |
| P2 | `poster_key`、`rule_poster_key`、`wechat_group_qr_code_key` 和 `prize_money` 没有与表字段容量对应的长度限制，超长内容如何处理需要产品与数据负责人确认。 | 产品与赛事运营负责人 |
| P1 | 报名截止时间可晚于资格赛开始时间，且未校验报名截止时间与资格赛截止时间的关系；期望的时间窗口关系需要产品确认。 | 产品与赛事运营负责人 |
