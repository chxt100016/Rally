## 已确认

- [Q1] 费用修改是否受约球类型、状态或临近开始时间限制？
  > 按 Java 实现确认：MeetupPolicy.assertEditPrice 只调用 assertOwner；不检查约球类型、状态、开始时间或编辑锁定时间，因此赛事约球及 DRAFT、OPEN、ONGOING、FINISHED、CLOSED 均可修改。
  → 已落入触发、详细流程和服务边界。

- [Q2] 省略或提交空费用明细、空分摊列表时，是保留还是清空原值？
  > 按 Java 实现确认：每次新建 CostData 并直接写入请求的 costItems、hourlyAllocations，所以 null 或空列表都会替换原值，不是局部更新。
  → 已落入接口契约、详细流程和成功响应。

- [Q3] 费用项和按人时分摊目前实际校验哪些空值、重复与覆盖规则？
  > 按 Java 实现确认：费用项名称、金额、空项目、负数等均不校验。非空分摊列表只校验总时长等于约球时长、每段时长>0、用户列表非空且用户是创建者或有效参与者；空时长在求和时先触发系统异常，空用户编号在参与者判断时也可能系统异常；重复用户、跨段重复、覆盖范围与段数均不校验。
  → 已落入接口契约、详细流程和异常分支后的边界说明。
