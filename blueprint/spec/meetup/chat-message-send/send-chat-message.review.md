## 已确认

- [Q1] 待审核报名者和已结束或已关闭约球是否仍允许发送消息？
  > 按 Java 实现确认：Meetup.assertIn 接受创建者以及 PENDING、JOINED、REVIEWED、SKIPPED 报名；发送流程不检查约球状态，因此 DRAFT、CLOSED、FINISHED 也不在此处拦截。
  → 已落入触发、详细流程和服务边界。

- [Q2] 发送消息时哪些人的未读数会增加，尚无聊天成员记录的参与者如何处理？
  > 按 Java 实现确认：只对 chat_user 中该约球已有且非发送者的记录执行 unread_count+1；尚无记录或已退出聊天的参与者不会因本次发送建立记录，之后拉取时才为本人建立。
  → 已落入详细流程、阅读状态活动和异常分支后的边界说明。

- [Q3] 消息保存、未读数递增、发送者已读推进和头像地址转换之间如何保证一致性与幂等？
  > 按 Java 实现确认：没有请求幂等键、显式事务或补偿。消息先保存，再依次递增未读数、推进发送者已读，最后转换头像地址；任一步失败都可能保留此前结果，重试会建立另一条消息。
  → 已落入触发、流程图和异常分支。
