## 已确认

- [Q1] 约球关闭资格如何结合实际状态与是否存在其他有效参与者判断？
  > 按 Java 实现确认：先按时间取得 realStatus。无其他有效参与者时仅 CLOSED 被拒绝，FINISHED 仍可关闭；有其他有效参与者时 FINISHED 与 CLOSED 均拒绝，DRAFT、OPEN、ONGOING 可关闭。有效参与者由 JOINED、REVIEWED、SKIPPED 报名判断。
  → 已落入详细流程、流程图和异常分支。

- [Q2] 关闭处罚何时触发，当前是否真正修改发布者信誉分？
  > 按 Java 实现确认：仅当 currentPlayers>1 时读取四档配置并计算处罚；处罚大于零也只有日志和 TODO，没有调用评分域，因此不会修改信誉分。该人数口径与关闭资格的报名口径并不完全相同。
  → 已落入成功响应、详细流程和技术线索。

- [Q3] 关闭事务与异步通知的边界是什么，发送前成员校验异常如何处理？
  > 按 Java 实现确认：close 方法有事务，通知注册为事务提交后异步执行，异常被吞掉且不影响关闭。发送前应过滤已退出者；若过滤器本身异常则 fail-open，继续尝试发送以避免漏发。
  → 已落入触发、详细流程、流程图和通知异常说明。

- [Q4] 取消通知是否必须作为关闭事务提交后的独立业务活动编排？
  > 是。关闭事务提交后独立编排参与者取消通知，通知结果不改变关闭终态。
  → 已落入业务活动、流程图与详细流程。

- [Q5] 通知候选人是否仅包含 JOINED、REVIEWED、SKIPPED 且排除发布者？
  > 是。候选人只取 JOINED、REVIEWED、SKIPPED，并排除发布者；发送前再次确认资格。
  → 已落入详细流程第 6 步。

- [Q6] 通知不可达或发送失败是否应回滚约球关闭结果？
  > 不回滚。不可达记 SKIPPED，渠道或发送失败记 FAILED，约球保持 CLOSED。
  → 已落入详细流程第 7 步与异常分支。
