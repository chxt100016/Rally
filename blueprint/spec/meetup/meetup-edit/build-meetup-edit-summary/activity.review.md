## 已确认

- [Q1] 摘要基于请求、原对象还是保存后的内存对象，返回哪些范围？
  > 基于 revise 后同一个 MeetupData 内存对象组装；返回约球基本编辑字段、存储状态和创建时间，不含参与者、actionState、recap 或人时分摊。若映射缺陷覆盖 bizId/cityName/createTime，摘要也返回覆盖后的值。
  → 已写入活动契约、业务动作 A1/A3、详细流程第 1-3 步与边界情况

- [Q2] 背景如何解析，球场缺失、天气与时段如何降级？
  > 按最终 courtId 通过 @court.court 取 surface/type，缺失则 null；天气模块未上线固定按晴天。背景按枚举结合开始时间：17:00-19:00 黄昏，19:00-次日06:00 夜间，其余白天，并返回资源 key/字段。
  → 已写入 reads、业务动作 A2、详细流程第 4-5 步与边界情况

- [Q3] 摘要或背景失败与事务、资源签名的关系是什么？
  > 该活动仍在 edit 应用事务调用链内；映射或背景解析异常报 SYSTEM_ERROR 并使上游保存事务回滚（若错误目标更新已发生也依赖同事务回滚）。只返回背景键/映射结果，不写库、不缓存；不发送通知。
  → 已写入异常分支、详细流程第 6 步与实现提示

- [Q4] 摘要是否继续直接使用上游保存后的同一内存对象？
  > 是。摘要继续反映上游同一内存对象，包括现有映射覆盖结果。
  → 已落入活动契约与详细流程第 1 步。

- [Q5] 球场不存在时是否继续用空材质环境和固定晴天规则形成背景？
  > 是。保留当前背景降级和固定天气、时段口径。
  → 已落入详细流程第 4、5 步与边界情况。

- [Q6] 摘要或背景形成失败是否继续让整个编辑事务回滚？
  > 是。该活动仍在编辑事务调用链内，失败触发整体回滚。
  → 已落入详细流程第 6 步与异常分支。
