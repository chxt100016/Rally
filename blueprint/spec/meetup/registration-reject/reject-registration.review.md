- [Q1] 拒绝待审核报名是否受约球状态、加入方式或报名到期时间限制？
  > 按 Java 实现确认：Meetup.reject 只校验报名存在、当前用户是创建者和报名 PENDING；不调用 isActive，不检查 joinMode、expiresAt，因此所有约球状态下的 PENDING 均可拒绝。
  → 已落入详细流程、异常分支和服务边界。

- [Q2] 拒绝是否记录审批时间、拒绝原因并通知申请人？
  > 按 Java 实现确认：只 setStatus(REJECTED)，不设置 optTime；命令没有拒绝原因字段，不保存理由；应用服务没有发申请人通知，只记录服务日志。
  → 已落入成功响应、详细流程和服务边界。

- [Q3] 审批通过、拒绝和申请人撤回并发处理同一报名时如何防止状态覆盖？
  > 按 Java 实现确认：聚合加载后在内存校验与改状态，保存按 bizId 更新，没有当前状态条件或版本号。多个事务都读到 PENDING 时可各自通过校验，后提交可能覆盖先提交；没有冲突优先级或补偿。
  → 已落入触发、详细流程和异常分支后的并发说明。

- [Q4] 拒绝接口是否接收订阅场景或登记通知额度？
  > 不接收订阅相关字段，不登记订阅额度，也不发送拒绝通知；拒绝事务只修改报名状态并记录应用日志。
  → 已落入请求参数、流程图和服务边界。

- [Q5] 拒绝 PENDING 报名是否继续不校验约球生命周期状态？
  > 是。保持现有代码，只校验约球、发布者、报名归属与 PENDING 状态。
  → 已落入详细流程第 3 步与异常分支说明。

- [Q6] 拒绝是否继续不记录 opt_time 与拒绝理由？
  > 是。保持现有数据写入，不新增审批时间或拒绝理由。
  → 已落入详细流程第 4 步与技术线索。

- [Q7] 拒绝成功是否继续不通知申请人且不返回报名详情？
  > 是。维持空成功响应，不新增通知与详情返回。
  → 已落入接口契约、详细流程第 6 步与异常分支说明。
