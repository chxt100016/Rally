## 已确认

- [Q1] 拒绝待审核报名是否受约球状态、加入方式或报名到期时间限制？
  > 按 Java 实现确认：Meetup.reject 只校验报名存在、当前用户是创建者和报名 PENDING；不调用 isActive，不检查 joinMode、expiresAt，因此所有约球状态下的 PENDING 均可拒绝。
  → 已落入详细流程、异常分支和服务边界。

- [Q2] 拒绝是否记录审批时间、拒绝原因并通知申请人？
  > 按 Java 实现确认：只 setStatus(REJECTED)，不设置 optTime；命令没有拒绝原因字段，不保存理由；应用服务没有发申请人通知，只记录服务日志并登记发布者授权。
  → 已落入成功响应、详细流程和服务边界。

- [Q3] 审批通过、拒绝和申请人撤回并发处理同一报名时如何防止状态覆盖？
  > 按 Java 实现确认：聚合加载后在内存校验与改状态，保存按 bizId 更新，没有当前状态条件或版本号。多个事务都读到 PENDING 时可各自通过校验，后提交可能覆盖先提交；没有冲突优先级或补偿。
  → 已落入触发、详细流程和异常分支后的并发说明。

- [Q4] 发布者本次通知授权场景如何筛选、去重，登记失败是否回滚拒绝？
  > 按 Java 实现确认：parseScenes 接受所有 NoticeScene 枚举名，非法项忽略、重复不去重。grant 在同一应用事务末尾调用但内部捕获异常，因此登记失败不抛出、不回滚已保存的 REJECTED。
  → 已落入请求参数、流程图和异常分支后的授权说明。
