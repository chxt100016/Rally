## 已确认

- [Q1] 是否改变详情可见范围、分享归因或邀请关系？
  > 按 Java 实现确认：shareUserId 仅在非 null 时写一条日志，不改变可见范围，不记录分享归因，不建立邀请关系，也不进入响应。任何已登录用户只要约球存在即可查询。
  → 已落入触发、请求参数、详细流程和服务边界。

- [Q2] 详情中的约球存储状态与按当前时间计算的操作状态冲突时分别如何交付？
  > 按 Java 实现确认：meetup.status 原样交付存储状态；actionState 使用 getRealStatus 按当前时间重算。两者可能暂时不一致，流程不做同步写入或校准。创建者且无其他有效参与者时，除 CLOSED 外即使实际 FINISHED 也优先返回 OWNER_EDITABLE。
  → 已落入成功响应、详细流程和技术线索。

- [Q3] 费用和发布者收款码对未报名陌生人是否可见，分摊人数按什么口径？
  > 按 Java 实现确认：只要有费用明细，COLLECTOR、PAYER、STRANGER 都收到费用视图，并在发布者有收款码时都收到签名 URL。实际状态 OPEN 按 maxPlayers 计算人均数，其他状态按发布者加有效参与者数量计算。
  → 已落入成功响应、详细流程和异常分支后的费用说明。

- [Q4] 进行中约球的复盘向哪些登录用户展示， 的实际含义是什么？
  > 按 Java 实现确认：meetup.canReview 对实际 ONGOING 或 FINISHED 为真，不再按用户是否参与过滤，所以所有已登录查询者都可收到复盘。scoreFilled 只是该约球是否存在任意比分记录，不表示当前用户是否填过比分。
  → 已落入成功响应、详细流程、复盘活动和服务边界。
