## 已确认

- [Q1] 待译清单的冻结时点、顺序与批次边界如何定义？
  > 请求开始时一次性读取 translated_text 为空串的全部记录，初始清单随后固定；按仓储返回顺序每 50 条分批，处理中新增条目不纳入，且不额外排序。
  → 已写入业务动作 A1-A2、详细流程第 1-3 步与边界情况

- [Q2] 外部整批失败、空白译文及数量异常如何影响后续批次和成功计数？
  > DeepSeek 返回 null 或数量不符时该批计 0 并继续后续批次；数量一致后逐条 trim，空白译文跳过，非空译文才保存并累计；不重试、不保存部分异常批。
  → 已写入异常分支、业务动作 A3-A4、详细流程第 4-6 步

- [Q3] 批量保存、缓存失效和中途数据库失败的原子性如何处理？
  > 每批非空译文一次批量更新 id 与 translated_text，成功后失效本地翻译缓存；批次间无总事务。读取或保存失败以 SYSTEM_ERROR 终止，此前成功批次保留，当前及后续保持原状。
  → 已写入领域依赖、异常分支、详细流程第 7 步与实现提示
