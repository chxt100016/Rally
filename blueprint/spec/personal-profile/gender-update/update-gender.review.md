## 已确认

- [Q1] 性别可从哪些原值改到哪些新值，是否限制频次、档案状态或重复提交？
  > MALE、FEMALE、UNDISCLOSED 之间可任意覆盖，包括提交当前值；除非字段为空或枚举无法解析，没有修改次数、时间、网球档案状态、已有约球或赛事关系限制。
  → 已在触发、详细流程、异常说明和服务边界明确三种枚举可任意覆盖，无频次、状态和重复提交限制。

- [Q2] 性别修改是否记录审计并回写历史比分或重新校验已有参与关系？
  > 不记录独立审计，不保存原性别或修改原因；不回写历史比分的性别快照，也不主动重查或撤销已有约球报名、赛事报名与比赛安排。后续业务读取当前性别时再按各自规则判断。
  → 已在详细流程、技术线索和服务边界明确无审计、无历史快照回写、无既有关系重审。

- [Q3] 返回个人档案的组装失败是否会回滚已保存的性别？
  > 会。updateGender 标注 @Transactional，保存后同步调用 getMyProfile；聚合运行时异常会穿过事务代理，用户表更新随事务回滚。
  → 已在触发、详细流程、流程图和异常分支明确保存与聚合同一事务，聚合失败回滚性别。

- [Q4] 没有网球档案、待完善、正常和核查期分别返回哪些内容？
  > 无 tennis profile 返回 NONE 与基础资料；TBC 只返回状态和基础资料；NORMAL 与 UNDER_REVIEW 还返回关注/粉丝/完成约球统计、NTRP 与提示、综合评级和三项评分、视频及上传限制。
  → 已在契约和详细流程区分 NONE、TBC 与 NORMAL、UNDER_REVIEW 的返回内容。
