## 已确认

- [Q1] 本人没有收款码或重复删除时返回成功还是失败？
  > 失败。第一次 get 可返回 null 并跳过七牛，但 UserExtDomainService.delete 会再次查询并断言存在，最终抛 USER_EXT_NOT_FOUND；重复删除不具备幂等成功语义。
  → 已在触发、流程图、异常分支和服务边界明确无资料及重复删除均报 USER_EXT_NOT_FOUND。

- [Q2] 七牛文件不存在与其他删除失败分别如何影响数据库资料删除？
  > 七牛 QiniuException code=612 被吞掉并继续删除 user_ext；其他 code 转为 RuntimeException，事务方法异常退出，数据库资料保留。图片实际状态仍以外部结果为准。
  → 已在详细流程、流程图、异常分支和技术线索区分七牛 612 继续与其他错误终止。

- [Q3] 外部图片删除成功但数据库删除失败时是否能事务回滚或补偿图片？
  > 不能。Spring 事务只覆盖数据库；七牛调用发生在数据库删除之前，外部删除已成功后，即使 user_ext 删除或事务提交失败，数据库可回滚但图片不会恢复，也没有补偿或重试任务。
  → 已在详细流程、异常分支和服务边界明确外部删除不受数据库事务保护且没有恢复补偿。

- [Q4] 两次资料读取之间发生并发保存或删除时可能删除哪条资料和哪些图片？
  > 第一读取得旧 key 后，并发保存可更新同一 userId+extKey 行；流程先删旧图片，第二读再看到存在并按键删除当前行，因而新资料被删而新图片遗留。并发删除可让第二读为空，外部图片已删但本请求返回 USER_EXT_NOT_FOUND。
  → 已在详细流程和技术线索明确两次读取无一致性比较，以及并发保存、删除可能产生的不一致。

- [Q5] extValue 采用什么数据格式，删除前是否校验资源归属和类型？
  > 代码把 extValue 原样视为七牛 key，固定 extKey 为 wechat_payment_code。删除前不校验是否 URL/base64/key、文件存在、图片类型、资源归属或所有权；错误格式也可能被传给七牛删除。
  → 已在详细流程、异常说明和服务边界明确 extValue 原样作七牛 key 且无格式、类型和归属校验。
