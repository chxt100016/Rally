## 已确认

- [Q1] total、水平票、出勤票和标签数分别按什么粒度计数？
  > 水平票和出勤票各按对应 review 记录一条计一票；TAG 按逗号拆后的每个非空原字符串计一次。total 是三者之和，不是评价人数、评价记录总数或约球数。
  → 已在契约和详细流程明确各维度计数粒度及 total 为三类数量之和。

- [Q2] 同一条标签评价中的重复标签、空标签和纯空格标签如何处理？
  > 不做单条内去重，重复标签重复计数。tagCount 在 trim 前只排除长度为 0 的字符串，所以纯空格会计数；topTags 先 trim 再排空，纯空格不展示。逗号产生的空串不计。
  → 已在详细流程、异常说明和技术线索明确重复、空串与纯空格标签的不同口径。

- [Q3] 高频标签的数量上限、排序和同次数顺序是什么？
  > 固定最多 5 项，不读配置。按累计次数降序；底层 groupingBy 使用 HashMap，同次数没有显式名称或首次出现次序作为次级排序，因此顺序不稳定。
  → 已在契约、详细流程和技术线索明确固定五项、次数降序及同次数顺序不稳定。

- [Q4] 查询是否校验账户档案、约球参与和时间范围，异常持久化类型或空值如何处理？
  > 不校验账户、档案、约球、参与关系和时间。仓储把 review_type 转为枚举，未知值会在转换阶段失败；TAG 的 reviewValue 为 null 时 split 抛异常，空字符串则计 0 个标签并正常返回。
  → 已在触发、异常分支和服务边界明确不做关联校验，并记录未知类型与 null 标签值失败。
