## 已确认

- [Q1] 各字段为 null、空字符串或请求全部为空时分别如何修改？
  > MapStruct 对每个 null 字段执行 IGNORE，因此 null 保留原值且无法清除生日等字段；非 null 空字符串会覆盖字符串原值。空对象或全部字段 null 仍读取并 updateById 保存当前值，再返回当前档案。
  → 已在契约、详细流程、异常说明和服务边界明确 null 保留、空串清空、空请求仍保存并返回。

- [Q2] 是否校验昵称内容、生日范围、城市开放性以及头像资源存在与归属？
  > 均不校验。没有 Bean Validation；昵称、简介无长度内容规则，生日无未来或年龄检查，城市不检查存在或开放，头像只当资源 key 保存，不检查格式、文件存在、所有权或可访问性。
  → 已在契约、详细流程、异常说明和服务边界明确没有内容、年龄、城市开放性或头像资源校验。

- [Q3] 基础资料保存后，返回档案聚合失败是否会回滚本次修改？
  > 会。editUser 标注 @Transactional，保存后同步调用 getMyProfile；聚合阶段抛出的运行时异常会穿过事务代理并回滚用户更新，Controller 只在事务退出后把 BusinessException 转为失败结果。
  → 已在触发、详细流程、流程图和异常分支明确保存与聚合处于同一事务，聚合失败回滚修改。

- [Q4] 不同网球档案状态分别返回哪些聚合内容？
  > 没有 tennis profile 返回状态 NONE 与基础资料；TBC 同样只返回状态与基础资料。NORMAL、UNDER_REVIEW 还返回关注/粉丝/完成约球统计、NTRP 与提示、综合评级和三项评分、视频列表及上传限制。
  → 已在契约和详细流程区分 NONE、TBC 与 NORMAL、UNDER_REVIEW 的返回分组。

- [Q5] 城市、头像和视频资源在返回阶段有哪些会使整次请求失败的情况？
  > 非空未知 cityCode 在 CityConfig.cities.get(code).getName 处空指针；签名配置或七牛构址失败会异常；视频 key 无扩展名在生成封面时下标异常；无法解析状态或视频持久化数据、聚合依赖读取失败也会使事务回滚。空头像、空城市和空视频 key 的签名方法本身返回 null。
  → 已在详细流程、异常分支和技术线索明确未知城市、签名失败及无扩展名视频等失败点和回滚结果。
