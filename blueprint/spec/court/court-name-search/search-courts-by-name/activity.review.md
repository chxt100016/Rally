- [Q1] query 的长度、空白与大小写规则如何处理？
  > 流程按原始 Java 字符串长度判断，null 或长度小于 2 直接空列表；不 trim。长度至少 2 但全空白时仓储不追加名称条件，返回城市全部 ACTIVE 球场；普通关键词用数据库 LIKE，大小写取决于库排序规则。
  → 已写入触发条件、活动契约、详细流程第 1、3-4 步与边界情况

- [Q2] 搜索的城市、状态、名称字段、分页和排序口径是什么？
  > city_code 精确匹配且 status=ACTIVE；keyword 非空白时 name LIKE 或 alias LIKE。城市不核对名录，不分页、不限量、不追加排序。
  → 已写入业务动作 A1、详细流程第 2、4 步与边界情况

- [Q3] 结果字段转换与异常降级如何与城市清单保持一致？
  > 复用球场 DTO 映射：拆 alias/tags、映射环境展示名并解析 ext_data。扩展资料缺失时字段为空；不可识别的枚举转换异常按 SYSTEM_ERROR，不返回部分列表。
  → 已写入活动契约、异常分支、业务动作 A2-A3 与详细流程第 5 步
