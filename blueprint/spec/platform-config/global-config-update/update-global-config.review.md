## 已确认

- [Q1] 运营鉴权和请求字段的精确要求是什么，空字符串内容是否允许？
  > 由 X-Admin-Key 独立鉴权，不要求用户登录。key 必须非空白，configValue 与 version 只要求非 null；因此空字符串内容可进入业务校验，字符串型配置可最终保存为空。
  → 接口契约、详细流程第 1-2 步与鉴权/参数异常分支

- [Q2] 配置类型如何判定，首页与非首页内容分别怎样校验和规范化？
  > 仅三项 HOME_* 配置按 JSON 专用规则校验并重新序列化；其余项根据枚举默认值正则推断整数或小数并验证可解析性，其他字符串原样保留，不校验业务范围。首次记录 valueType 也按相同推断写入。
  → 详细流程第 3-4 步与校验异常分支说明

- [Q3] 首次发布、已有记录和停用记录的版本并发规则及写入字段是什么？
  > 无记录只接受 version=0，创建 enabled=true/version=1；已有记录（含停用）必须提交等于库版本的 version，条件更新值、说明、enabled=true、version+1。已有记录的 valueType 不更新。
  → 详细流程第 5-6 步与 OPERATION_FAILED 分支

- [Q4] 发布后配置缓存如何刷新，多实例是否同步，事务回滚能否恢复缓存？
  > 保存后在事务提交前执行 SystemConfig.init，仅重建当前 JVM 缓存，不广播其他实例。数据库回滚不能回滚静态内存：init 失败可能留下空或部分缓存，init 成功后若全量视图查询/提交失败则缓存可能保留未提交新值。
  → 详细流程第 7-8 步、SYSTEM_ERROR 分支与服务边界

- [Q5] 成功响应为何返回 64 项全量视图，保存或后续查询失败时如何收场？
  > updateAny 在保存和当前实例缓存刷新后调用 getAll，复用全量查询口径返回 64 项。保存返回 false给出配置保存失败；版本条件未命中给出并发提示；未处理异常及后续读取失败使数据库事务回滚且不返回部分视图，但内存缓存不具备事务补偿。
  → 接口契约、业务活动、详细流程第 8 步与失败收场

- [Q6] 首页合并后的唯一配置标识与根结构是什么？
  > 唯一配置标识为 home.page.config，配置值是根对象，根对象只承载有序 sections 数组。
  → 已落实到接口契约、详细流程第 3 步和技术线索：唯一 key 为 home.page.config，根对象包含 sections。

- [Q7] 旧的三项首页配置如何退出，默认首页内容如何保留？
  > home.layout.config、home.tournament.poster.config、home.poster.config 退出已登记名录且不再运行时读取；home.page.config 的内置默认 JSON 合并保留原有五个区域和默认海报内容，数据库中的旧覆盖记录不再生效但不在本次删除。
  → 已落实到详细流程第 3 步与首页默认配置约束：旧三项 key 退出名录，默认大 JSON 保留原首页内容。

- [Q8] 统一海报区域与单张海报的交互字段采用什么结构？
  > 区域类型统一为 POSTER，可出现多次；区域内直接包含 title、subtitle、cityAware 和 posters。单张海报使用 actionType 表示 NAVIGATE 或 PREVIEW，并保留图片、文案及各端跳转目标。
  → 已落实到首页结构校验规则：区域统一为 POSTER，单张海报使用 actionType。

- [Q9] 海报 cityId 的缺省、匹配与发布校验口径是什么？
  > cityId 是单张海报的可选字符串；缺失、null 或空白表示所有城市可见，非空时与首页请求最终采用的 cityCode 精确匹配。发布时只校验其为字符串，不要求已存在于城市名录。
  → 已落实到首页结构校验与异常分支：cityId 可缺失/null/空白，非空仅校验字符串，不校验城市名录。

- [Q10] 完整首页配置发布时，占位符是否只允许出现在 poster 的 wechatUrl、appUrl、webUrl 中，且当前仅允许 {{cityId}} 与 {{cityName}}？
  > 是，只检查 poster 的 wechatUrl、appUrl、webUrl；当前仅登记 {{cityId}} 与 {{cityName}}。
  → 落实到首页 JSON 校验步骤、异常分支和 POSTER 规则。

- [Q11] URL 中出现未闭合的 {{、多余的 }} 或任意其他 {{...}} 标记时，是否都按无效占位符拒绝整份配置？
  > 是；未闭合的 {{、无配对的 }}、空占位符及任何未登记的 {{...}} 都拒绝整份配置。
  → 落实到 PARAM_ERROR 异常分支和占位符语法校验。

- [Q12] 旧 cityAware 字段是否作为未识别扩展字段原样保留但不再校验、不再产生运行效果？
  > 是；cityAware 从已识别字段退出，按其他未知字段原样保留，但发布和首页查询都忽略它。
  → 落实到首页 JSON 规范化和向后兼容说明。
