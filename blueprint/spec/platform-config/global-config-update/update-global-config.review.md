## 已确认

- [Q1] 运营鉴权和请求字段的精确要求是什么，空字符串内容是否允许？
  > 由 X-Admin-Key 独立鉴权，不要求用户登录。key 必须非空白，configValue 与 version 只要求非 null；因此空字符串内容可进入业务校验，字符串型配置可最终保存为空。
  → 接口契约、详细流程第 1-2 步与鉴权/参数异常分支

- [Q2] 配置类型如何判定，首页与非首页内容分别怎样校验和规范化？
  > 仅三项 HOME_* 配置按 JSON 专用规则校验并重新序列化；其余项根据枚举默认值正则推断整数或小数并验证可解析性，其他字符串原样保留，不校验业务范围。首次记录 valueType 也按相同推断写入。
  → 详细流程第 3-4 步与校验异常分支说明

- [Q3] 首次发布、已有记录和停用记录的版本并发规则及写入字段是什么？
  > 无记录只接受 version=0，创建 enabled=true/version=1；已有记录（含停用）必须提交等于库版本的 version，条件更新值、说明、enabled=true、version+1。已有记录的 valueType 不更新。
  → 详细流程第 5-6 步与 OPERATION_FAILED 分支

- [Q4] 发布后配置缓存如何刷新，多实例是否同步，事务回滚能否恢复缓存？
  > 保存后在事务提交前执行 SystemConfig.init，仅重建当前 JVM 缓存，不广播其他实例。数据库回滚不能回滚静态内存：init 失败可能留下空或部分缓存，init 成功后若全量视图查询/提交失败则缓存可能保留未提交新值。
  → 详细流程第 7-8 步、SYSTEM_ERROR 分支与服务边界

- [Q5] 成功响应为何返回 64 项全量视图，保存或后续查询失败时如何收场？
  > updateAny 在保存和当前实例缓存刷新后调用 getAll，复用全量查询口径返回 64 项。保存返回 false给出配置保存失败；版本条件未命中给出并发提示；未处理异常及后续读取失败使数据库事务回滚且不返回部分视图，但内存缓存不具备事务补偿。
  → 接口契约、业务活动、详细流程第 8 步与失败收场
