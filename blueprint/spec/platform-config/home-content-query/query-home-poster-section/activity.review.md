## 已确认

- [Q1] 三种海报区域分别从哪里取文案和海报？
  > 赛事区读赛事海报配置且区域文案优先；球场区读通用海报并用城市默认文案；自定义区直接用区域内文案和海报。
  → 已写入业务动作 A1 与详细流程第 1-3 步

- [Q2] 城市参数何时以及如何附加？
  > 球场区总附加，自定义仅 cityAware=true，赛事区不附加；非空URL直接追加 ?cityCode&cityName&mode=view，不判断已有查询串也不编码。
  → 已写入业务动作 A2、详细流程第 2-4 步与边界情况

- [Q3] 单个海报转换失败后保留什么？
  > 数组级捕获，保留失败前已形成项并停止后续；若失败发生在球场副标题城市解析则整个区域省略。
  → 已写入异常分支、业务动作 A3、详细流程第 5 步与边界情况

- [Q4] cityId 的空白判断和与 cityCode 的比较是否裁剪或规范化？
  > cityId 为 null、缺失或 trim 后为空时视为全城市；其他值不裁剪、不大小写转换，与最终采用的 cityCode 原字符串精确比较。
  → 已落实到业务动作 A1、详细流程第 1 至 2 步和边界情况。

- [Q5] cityAware 海报遇到未知城市时，哪些海报需要省略，其他海报如何继续？
  > cityAware=false 时完全不查城市名。cityAware=true 且当前海报至少有一个非空导航目标时才取城市名；城市未知则只省略当前海报并继续后续海报。没有导航目标的海报不依赖城市名，仍可交付。
  → 已落实到业务动作 A3、详细流程第 5 步和边界情况。

- [Q6] 可见海报发生 actionType、图片签名或字段异常时，采用单项跳过还是停止后续列表？
  > 保持现有部分成功语义：首个可见海报转换异常终止该区域后续海报处理，保留此前已形成海报。cityId 不匹配不是异常，直接跳过并继续。
  → 已落实到详细流程第 3 至 4 步和 POSTER_PARTIAL 异常分支。

- [Q7] cityAware 导航遇到已有查询参数和中文城市名时是否改变现有拼接与编码规则？
  > 不扩大本次变更范围，保持当前客户端约定：直接追加 ?cityCode=<code>&cityName=<name>&mode=view，不识别已有查询参数且不额外 URL 编码。
  → 已落实到详细流程第 6 步和边界情况，保持当前拼接与编码约定。

- [Q8] 占位符替换是否对 NAVIGATE 和 PREVIEW 海报的三个 URL 一视同仁，null 或空白 URL 保持原值？
  > 是，三个 URL 的占位符规则不区分 NAVIGATE/PREVIEW；null 或空白 URL 原样保留。
  → 落实到活动契约、A2 与边界情况。

- [Q9] 同一海报任一 URL 使用 {{cityName}} 时是否只需取得一次城市名，并用于该海报三个 URL 的全部出现位置？
  > 是，同一海报只取得一次城市名，替换三个 URL 中全部 {{cityName}}。
  → 落实到 A2 的城市名解析与替换规则。

- [Q10] 合法占位符替换是否发生在图片签名之后；城市名不可用时即使图片已签名也只省略当前海报，不影响后续海报？
  > 否；先校验并替换 URL 占位符，城市名不可用时直接省略当前海报，再对可形成海报签名图片，避免无效签名。
  → 落实到 A2/A3 的动作顺序和详细流程。
