## 已确认

- [Q1] 定时任务在什么开关和 cron 配置下运行，一次扫描哪些赛事？
  > 仅 job.tournamentMatch.enabled=true 时装配；按 job.tournamentMatch.cron 执行，缺省 0 0 2 * * ?，未另指定时区。每次按当前时间查询 ACTIVE 且 qualifierStartTime 已到的全部赛事，不检查报名截止、资格赛截止、赛事结束时间或轮次完成度。
  → 已写入触发、详细流程第 1-2 步与技术线索

- [Q2] 定时入口是否接受手工分组或临时排除，自动匹配规则与 HTTP 全量模式是否一致？
  > 定时入口无请求参数，不支持手工分组或临时排除。它与 HTTP 无参数全量模式调用同一应用入口，逐赛事使用相同当前轮次候选池、自动分组、比赛建立与通知逻辑。
  → 已写入接口契约、详细流程第 3-5 步与服务边界

- [Q3] 单个赛事失败、没有可行分组或通知失败时，其他赛事和已提交结果如何处理？
  > 无可行组时该赛事保持原状并正常继续。每个赛事匹配在独立事务中执行，异常时该赛事未提交变化回滚并继续下一个，其他已成功结果保留；通知缺失或发送失败不回滚已建立比赛和报名。
  → 已写入详细流程第 6-7 步、异常分支与技术线索

- [Q4] 每日任务是否继续只扫描 ACTIVE 且资格赛开始时间已到的赛事？
  > 是。维持当前扫描条件，不增加报名截止、资格赛截止或赛事结束过滤。
  → 已落入触发、详细流程第 2 步与异常分支。

- [Q5] 单个赛事处理失败时是否继续隔离失败并处理其他赛事？
  > 是。单赛事事务失败只记录异常并继续，已提交赛事结果保留。
  → 已落入详细流程第 7 步与异常分支。

- [Q6] 定时任务是否继续不交付比赛清单、失败赛事或通知结果？
  > 是。定时入口无业务响应，也不产生对外失败明细。
  → 已落入接口契约。
