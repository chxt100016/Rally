## 概要

按冻结时间找出所有已到期且仍活跃的约球结算候选。

## 职责

| 范围 | 内容 |
|---|---|
| 做什么 | 在一次只读快照中跨约球筛选结束时间已到且语义状态仍活跃的记录，返回候选约球编号与判定依据 |
| 不做什么 | 不批量更新 `rally_meetup`；不直接把约球置为结束；不调度、分页重试、记录日志或发送结束通知 |
| 为什么不是聚合 | 规则要跨越任意数量的约球实例才能形成候选集合，结论不属于某一场约球；服务本身不持有状态 |
| 前置校验边界 | 候选只是查询快照上的预判，不是最终状态保证；实际结束前必须由约球聚合按最新状态和时间再次校验 |

## 契约

### 输入

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| settlementAt | LocalDateTime | 是 | 调用开始时冻结的统一结算基准，不得在逐条处理中重复取当前时间 |

### 输出

| 字段 | 类型 | 说明 |
|---|---|---|
| candidates | 候选列表 | 每项包含 `meetupId`、查询时语义状态、`endTime` 与结论 `DUE_TO_FINISH` |
| candidateCount | Integer | 候选列表条数，可为 0 |

## 规则

R1 仅语义状态为 `OPEN`、`FULL`、`ONGOING` 的约球属于活跃候选范围；`DRAFT`、`CLOSED`、`FINISHED` 及未知状态都不候选。
R2 `end_time` 非空且小于或等于 `settlementAt` 时判定已经到期；晚于基准或结束时间为空时不候选。
R3 状态比较使用统一领域枚举；持久化查询可兼容历史大小写值，但输出必须归一为大写语义状态。
R4 一次调用只使用同一个 `settlementAt` 和同一数据库读取快照，返回顺序不构成业务保证。
R5 服务只返回候选，不修改任何约球。候选交给约球聚合时必须重新验证当前仍活跃且当前时间不早于结束时间。

## 边界情况

- 没有命中记录：返回空列表和 0，不视为失败。
- 结束时间恰等于基准：进入候选。
- 历史状态保存为 `full`、`Full` 等大小写变体：适配器归一后按 `FULL` 候选；未知拼写不候选。
- 查询后约球被关闭或结束时间被延后：候选仍保留查询时事实，但后续聚合命令按最新状态拒绝结束。
- 查询后新产生到期约球：不补入本次快照，等待下一次调用。
- 单个候选处理失败：不影响该只读候选清单；重试与继续策略属于调用活动。
- 候选数量很大：契约本身不规定分页；实现可流式读取，但所有页必须使用同一冻结基准。

## 实现提示

查询只投影 `biz_id`、`status`、`end_time`。迁移期 SQL 可用大小写归一匹配活跃状态，但领域输出统一枚举。现有直接批量 UPDATE 需要在实现阶段拆为“只读候选 + 逐聚合结束”，避免领域服务绕过 `@meetup.meetup` 的状态不变量。
