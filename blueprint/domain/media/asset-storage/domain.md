## 概要

为受限资源键签发上传、临时读取和幂等删除能力。

## 职责

| 范围 | 内容 |
|---|---|
| 做什么 | 校验资源键及允许命名空间；签发精确键或前缀受限的上传授权；生成限时读取 URL；执行幂等对象删除 |
| 不做什么 | 不读取或修改业务表；不判断用户是否拥有资源；不验证媒体内容、对象是否存在或是否已被业务记录引用；不参与数据库事务或恢复已删除对象 |
| 为什么不是聚合 | 授权、签名和删除在任何业务聚合被创建前都可调用，服务自身不保存需要事务维护的领域状态 |
| 前置校验边界 | 服务只保证授权 scope、键格式和外部调用结论；资源归属、业务配额、文件类型及后续是否登记由调用活动或聚合保证 |

## 契约

### 输入

| 操作 | 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|---|
| 签发上传授权 | scopeMode | Enum | 是 | `EXACT_KEY` 或 `KEY_PREFIX` |
| 签发上传授权 | resourceScope | String | 是 | 安全资源键或以 `/` 结尾的安全前缀，必须位于调用方给出的允许命名空间 |
| 签发上传授权 | allowedNamespace | String | 是 | 例如 `avatar/`、`user/{userId}/`、`videos/{userId}/` |
| 签发上传授权 | maxBytes | Long | 是 | 必须大于 0 |
| 签发上传授权 | expiresInSeconds | Long | 是 | 必须大于 0 |
| 签发读取 URL | resourceKey | String | 是 | 安全、非空对象键 |
| 签发读取 URL | expiresInSeconds | Long | 是 | 必须大于 0 |
| 删除对象 | resourceKey | String | 是 | 安全、非空对象键；业务所有权已由调用方确认 |

### 输出

| 操作 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 签发上传授权 | outcome | Enum | `AUTHORIZED` 或 `REJECTED` |
| 签发上传授权 | uploadToken | String? | 授权成功时返回，scope 与输入模式严格一致 |
| 签发上传授权 | expiresAt | Instant? | 令牌实际截止时间 |
| 签发读取 URL | outcome | Enum | `SIGNED` 或 `REJECTED` |
| 签发读取 URL | signedUrl | String? | 签名成功时返回；不代表对象存在 |
| 签发读取 URL | expiresAt | Instant? | URL 实际截止时间 |
| 删除对象 | outcome | Enum | `DELETED`、`ALREADY_ABSENT` 或 `FAILED` |

## 规则

R1 资源键和前缀必须为相对路径，拒绝空白、前导 `/`、反斜杠以及值为 `.` 或 `..` 的路径段；授权 scope 还必须位于 `allowedNamespace` 内。
R2 `EXACT_KEY` 授权只能写入指定完整键；`KEY_PREFIX` 授权只能写入指定前缀下的键，最终令牌必须保留前缀 scope，禁止降级为整个桶。
R3 上传授权必须把正数 `maxBytes` 和实际截止时间写入最终策略；SDK 二次构造令牌时不得丢失或覆盖这些限制。
R4 临时读取 URL 的截止时间按签发时刻加正数 TTL 计算；签名只证明在期限内拥有访问凭据，不探测对象是否存在。
R5 删除操作是幂等的：外部存储明确返回“对象不存在”时结论为 `ALREADY_ABSENT`，与正常 `DELETED` 都可被调用方视为删除完成。
R6 服务不从用户编号猜测所有权。调用方必须先根据自身聚合规则给出允许命名空间或已确认的删除 key，服务只执行格式与 scope 校验。

## 边界情况

- 同一秒为同一精确键签发多次：允许返回多个有效令牌；上传时可能互相覆盖，键生成的去重责任属于调用方。
- 前缀为 `videos/{userId}/`：令牌只能写该目录，返回的前缀不是提示文本而是实际授权边界。
- `type` 等业务输入含 `/`、`..` 或反斜杠：调用方生成的 key 在 R1 被拒绝，不签发授权。
- `maxBytes` 为 0 或负数：拒绝签发，不能产生“0MB”或无限制令牌。
- 对不存在对象签发读取 URL：可以返回 `SIGNED`；实际读取可能由对象存储返回不存在。
- 重复删除或对象原本不存在：返回 `ALREADY_ABSENT`，不作为业务失败。
- 外部删除成功后数据库事务失败：对象不会自动恢复；调用方必须接受失效引用风险或采用提交后删除/补偿任务。
- 外部凭据、桶或域名无效：返回相应操作的失败结论，不持久化授权结果。

## 实现提示

七牛适配器要在最终 `putPolicy` 上保留 `scope`、`isPrefixalScope`、`fsizeLimit` 与 deadline，避免调用 SDK 的桶级便捷方法覆盖前缀策略。域名协议、路径拼接和签名截止时间集中处理；将七牛“文件不存在”状态映射为 `ALREADY_ABSENT`，其余异常保持为基础设施失败供活动映射。
