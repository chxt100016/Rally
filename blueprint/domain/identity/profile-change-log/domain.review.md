## 已确认

- [Q1] 档案变更日志是否是可修改的用户子实体，还是建立后不可变的独立聚合？
  > 作为独立、追加式聚合；每条日志建立后业务字段不可修改，不并入用户聚合。用户档案与日志可由上层事务共同提交，但各自维护自己的不变量。
  → 聚合根、边界、RECORDED 状态与 I1

- [Q2] type 与 reason 的持久化大小写采用什么规范，以解决 UNDER_REVIEW 写入和 under_review 查询不一致？
  > 领域值统一使用大写枚举语义，持久化统一映射为小写 snake_case；查询也必须通过同一映射，禁止直接使用枚举名字符串。
  → 命令后的枚举持久化规范与实现提示

- [Q3] refId 为空的自评日志是否需要由唯一约束保证重复请求幂等？
  > 不保证。refId 为空时每次有效提交都允许新增日志，包括同值自评；仅 refId 非空的来源事件按 userId、type、refId、reason 保证幂等。
  → I4 与 ref_id 为空/非空的边界情况
