## 概要

从一条地图场所记录算出球场环境、标签、坐标与展示资料。

## 职责

做：判定球场是室内还是室外；生成球场标签；把经纬度串拆成经度与纬度；把评分、人均消费、一周营业时间、联系电话整理成展示资料。

不做：不判定记录是否有效、不做就近合并（那是 `@court.court-poi-screener` 的事）；不生成球场名称拼音（那由球场聚合按名称自行保证）；不判定场地材质；不写库；不报错。

进不了任何聚合的理由：它的调用时机在球场聚合实例被创建之前——场所记录要先算出这些属性才能建成球场，此时还没有任何球场实例可以承载这段规则。

它给出的是预检结论，不是最终保证：球场环境与标签是从名称、地址等文本猜出来的，可能与实际不符，运营随时能用球场编辑改掉；字段长度上限由球场聚合在存入时按 `rally_court` 的列宽兜底。

## 契约

### 入参

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `name` | 字符串 | 是 | 场所名称 |
| `address` | 字符串 | 否 | 场所地址 |
| `poiType` | 字符串 | 否 | 地图返回的场所类型串 |
| `rectag` | 字符串 | 否 | 地图返回的推荐标签 |
| `keytag` | 字符串 | 否 | 地图返回的关键标签 |
| `location` | 字符串 | 否 | 经纬度串，形如 `经度,纬度` |
| `rating` | 字符串 | 否 | 评分 |
| `cost` | 字符串 | 否 | 人均消费 |
| `opentime` | 字符串 | 否 | 一周营业时间 |
| `tel` | 字符串 | 否 | 联系电话 |

### 出参

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `environment` | 枚举 | 否 | `INDOOR` 室内 / `OUTDOOR` 室外；判不出时为空 |
| `tags` | 字符串列表 | 是 | 命中的球场标签，按判定顺序排列，未去重；一条都没命中时为空列表 |
| `lng` | 小数 | 否 | 经度；经纬度串缺失或无法解析时为空 |
| `lat` | 小数 | 否 | 纬度；经纬度串缺失或无法解析时为空 |
| `profile` | 展示资料 | 是 | 含评分、人均费用、开放时间、联系电话；入参中缺哪项就不给哪项，全缺时为空 |

## 规则

R1 把名称、地址、场所类型串、推荐标签、关键标签拼成一段判定文本。
R2 判定文本含「室内」时，球场环境为 `INDOOR`，判定结束。
R3 判定文本含「楼顶」「天台」「屋顶」「露台」任一时，球场环境为 `OUTDOOR`，判定结束。
R4 地址中出现 3 到 9 的楼层写法（形如 `3F`、`3f`、`3楼`、`3层`）时，球场环境为 `OUTDOOR`，判定结束。
R5 判定文本含「公园」「广场」「体育场」任一时，球场环境为 `OUTDOOR`，判定结束。
R6 R2 到 R5 都不命中时，球场环境为空。
R7 标签按下列条件逐条判定，命中即按此顺序追加：名称或地址含「空调」加「空调」；含「楼顶」「天台」「屋顶」「露台」任一加「楼顶」；名称含「草地」加「草地」；名称含「红土」加「红土」；名称含「硬地」或「硬场」加「硬地」；名称或地址含「地铁」或地址含「站」加「近地铁」；名称或地址含「停车」或名称含 `parking`（不区分大小写）加「停车方便」；名称含「公园」「体育中心」「体育公园」任一加「公共设施」；评分可识别为数字且不小于 4.6 加「高评分」；一周营业时间含「24小时」或 `00:00-24:00` 加「24小时营业」；名称或地址含「灯光」或「夜间」加「有灯光」。
R8 球场环境为 `INDOOR` 时追加标签「室内场」，为 `OUTDOOR` 时追加「室外场」，为空时都不追加。
R9 经纬度串按英文逗号拆成两段，前段为经度、后段为纬度，任一段无法解析为小数时经度与纬度都给空。
R10 展示资料逐项判定：入参中该项为空白就不放进展示资料，非空白就原样放入，不做格式校验与单位换算。

## 边界情况

- 名称为空白：判定文本仍可由地址与标签构成，规则照常执行。
- 评分为非数字字符串：视为没有评分，不加「高评分」标签，展示资料里的评分仍按原样保留。
- 经纬度串格式异常（段数不为二、含非数字）：经度纬度都给空。
- 一条标签都没命中：标签为空列表，不是 null。
- 展示资料四项全为空白：展示资料为空。

## 实现提示

判定关键词表、评分阈值 4.6、楼层正则集中成常量；标签按 R7 的顺序追加即可，不排序、不去重，与现有抓取脚本的行为保持一致。
