## 概要

判定哪些地图场所记录是有效网球场，并把同一处场馆的多条记录归成一簇。

## 职责

做：对一批地图场所记录逐条判定有效性，给出保留与丢弃两组；对保留下来的记录按地理位置聚簇，每簇给出一条主记录与其余被并掉的记录。

不做：不发起任何地图请求；不解析球场环境、标签与展示资料（那是 `@court.court-profile-resolver` 的事）；不写库、不生成球场业务编号；不判断这条记录在库中是否已收录；不报错。

进不了任何聚合的理由：它的调用时机在球场聚合实例被创建之前——记录还没被解析成球场就要先筛掉无效的；聚簇判定还要跨越同一批里的多条记录两两比距离，结论不属于其中任何一条。

它给出的是预检结论，不是最终保证：聚簇只在单次抓取的这一批记录内成立，不与库中已有球场比对，因此同一处场馆仍可能因两次抓取取到不同的场所编号而在库中留下两条记录；库中记录的唯一性靠 `rally_court.source_id` 的唯一约束保证。

## 契约

### 入参

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `pois` | 场所记录列表 | 是 | 可为空列表。每条至少含场所编号、名称、地址、经纬度串、推荐标签、关键标签、评分 |

### 出参

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `clusters` | 簇列表 | 是 | 每项含一条主记录与一组被并掉的记录；入参为空列表时为空列表 |
| `rejectedCount` | 整数 | 是 | 未通过有效性判定被丢弃的记录条数 |
| `mergedCount` | 整数 | 是 | 通过判定但被并进其他记录的条数 |

## 规则

R1 记录名称或地址含「学练馆」「穿线」「培训中心」任一关键词时判定为无效，丢弃。
R2 记录的推荐标签与关键标签拼接后不含「网球场」时判定为无效，丢弃。
R3 R1 与 R2 任一命中即丢弃，两条都不命中才保留。
R4 两条记录的经纬度按 Haversine 公式算出的球面距离不超过 100 米时，判定为同一处场馆。
R5 同簇关系可传递：A 与 B 同处、B 与 C 同处时，A、B、C 同属一簇，即便 A 与 C 相距超过 100 米。
R6 每簇的主记录取评分最高的一条；评分为空或无法识别为数字时视为最低；多条评分相同时取其中任意一条。
R7 经纬度缺失或无法解析的记录不参与聚簇，各自单独成簇，自己即为主记录。

## 边界情况

- 入参为空列表：三项出参都为空或 0。
- 全部记录都被 R1 或 R2 丢弃：簇列表为空，丢弃条数等于入参条数。
- 一批记录全部经纬度缺失：每条各自成簇，被并掉条数为 0。
- 单簇内记录数量很大：不设上限，主记录只有一条，其余全部记为被并掉。

## 实现提示

聚簇用并查集实现，两两比距离在单批量级（一座城市数百条）下可以接受；100 米阈值与关键词表集中成常量，便于日后按城市调整。
