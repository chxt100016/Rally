## 概要

按编码在城市与区县名录中查名称，并推导一座城市下属的全部区县。

## 职责

做：按城市编码查城市中文名称，按区县编码查区县中文名称，按城市编码推导它下属的全部区县编码与名称。

不做：不判断城市是否已开通业务；不校验区县编码是否属于某座城市；不做名称到编码的反查；不做拼音或首字母检索；不维护名录数据本身；不报错——查不到就是查不到，给出「未命中」的结论，转不转成异常由调用方决定。

进不了任何聚合的理由：名录是随产品发布的静态行政区划数据，没有任何聚合实例承载它，而它的调用时机在球场聚合实例被创建之前——录入和抓取都要先解出归属名称才能建球场；推导下属区县这条规则还要跨越名录里的多条区县记录来判定归属，不属于任何单条记录。

它给出的是预检结论，不是最终保证：名录反映的是随包发布时的行政区划版本，可能落后于现实；球场归属数据的正确性靠球场聚合的不变量 `I4` 保证编码与名称成对，靠数据库约束保证城市编码非空。

## 契约

### 入参

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `code` | 字符串 | 是 | 六位行政区划编码 |
| `scope` | 枚举 | 是 | `CITY` 查城市名称 / `DISTRICT` 查区县名称 / `DISTRICTS_OF_CITY` 推导城市下属区县 |

### 出参

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `hit` | 布尔 | 是 | `scope` 为 `CITY` 或 `DISTRICT` 时表示编码是否在名录中命中；为 `DISTRICTS_OF_CITY` 时表示城市编码本身是否命中 |
| `name` | 字符串 | 否 | 命中时该编码对应的中文名称；`scope` 为 `DISTRICTS_OF_CITY` 时为该城市的名称 |
| `districts` | 区划项列表 | 否 | 仅 `scope` 为 `DISTRICTS_OF_CITY` 时给出，每项含区县编码与中文名称；该城市在名录中没有下属区县时为空列表 |

## 规则

R1 城市名称与区县名称分属两份名录，按 `scope` 决定查哪一份，两份互不回退：城市编码在区县名录里命中也算未命中。
R2 编码为空白、长度不足六位或在对应名录中找不到时，结论为未命中，名称为空。
R3 推导城市下属区县时，直辖市按编码前两位归属：城市编码为 `110000`、`120000`、`310000`、`500000` 时，区县编码前两位与城市编码前两位相同的即为它的下属区县。
R4 其余城市按编码前四位归属：区县编码前四位与城市编码前四位相同的即为它的下属区县。
R5 省直辖县级行政区（济源、仙桃、潜江、天门、神农架、海南十五个县市、新疆兵团十二市）在名录中按城市收录，不进区县名录：它们本身不设区，作为城市编码传入即可，作为区县编码查询则未命中。
R6 按 R3 或 R4 一个区县都推不出的城市（东莞、中山、三沙、儋州、嘉峪关，以及 R5 的省直辖县级行政区），下属区县给空列表，命中结论仍为真。
R7 下属区县按区县编码升序给出，同一编码在名录中重复出现时只取第一条。

## 边界情况

- 城市编码本身未命中：结论为未命中，名称与下属区县都为空，不再推导。
- 名录文件读取失败或为空：一律按未命中处理，不抛异常。
- 名录数据基于民政部 2023 年 1 月《县以上行政区划代码》，此后的区划调整不会自动跟进：撤销的区县照常推导出来，新设的区县推导不出来，本服务不做时效性修正，靠更新名录文件解决。

## 实现提示

城市名录与区县名录都是 classpath 下的静态 JSON（`city.json`、`district.json`），进程启动时一次性加载成两张按编码索引的表，以及一张城市编码到下属区县的预建映射，避免每次调用重扫全表。
