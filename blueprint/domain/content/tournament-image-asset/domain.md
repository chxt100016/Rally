## 概要

生成赛事主图与轻量背景图，并按固定对象键覆盖保存。

## 职责

| 范围 | 内容 |
| --- | --- |
| 做什么 | 校验原图可解码；分别生成 JPEG 主图与目标 50KB 的背景图；推导固定对象键；依次覆盖保存并给出完整或部分保存结论 |
| 不做什么 | 不修改赛事记录；不签发访问 URL；不检查上传请求的 multipart 大小；不为两个对象提供原子提交、版本冲突检测或失败补偿 |
| 为什么不是聚合 | 在任何赛事聚合被装载或更新前即可调用，且自身没有需要在数据库事务中维护的状态或一致性边界 |
| 前置校验边界 | 只对本次图片转换和对象写入给出结论；赛事图片是否最终可对外使用，由调用活动在后续绑定和查询流程中决定 |

## 契约

### 输入

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| tournamentId | Long | 是 | 必须为正数，用于生成稳定对象键 |
| sourceImage | Binary | 是 | 内容非空且可被图片解码器识别；入口大小限制由调用方负责 |

### 输出

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| outcome | Enum | `SUCCESS`、`FAILED_BEFORE_SAVE` 或 `FAILED_AFTER_MAIN_SAVE` |
| imageKey | String? | 主图对象键；主图保存成功后返回 |
| backgroundKey | String? | 背景图对象键；背景图保存成功后返回 |

## 规则

R1 主图与背景图都必须直接从同一份原图独立生成，禁止用主图的有损结果再次生成背景图。
R2 主图编码为 JPEG，质量参数为 `0.75`；背景图以 `50KB` 为压缩目标，但不承诺所有可解码图片都严格小于该值。
R3 主图键固定为 `tournament/{tournamentId}.jpg`，背景图键固定为 `tournament/{tournamentId}_background.jpg`；重复调用允许覆盖现有对象。
R4 必须先保存主图、再保存背景图。主图失败时结论为 `FAILED_BEFORE_SAVE`；背景图失败时保留已保存主图并返回 `FAILED_AFTER_MAIN_SAVE`，不得自动删除或回滚主图。
R5 同一赛事的并发写入不做版本仲裁，以对象存储最后完成的写入为最终内容。

## 边界情况

| 情况 | 处理 |
| --- | --- |
| 原图为空或无法解码 | 不执行任何对象写入，返回 `FAILED_BEFORE_SAVE` |
| 主图编码或保存失败 | 不尝试保存背景图，返回 `FAILED_BEFORE_SAVE` |
| 背景图编码或保存失败 | 保留主图，返回 `FAILED_AFTER_MAIN_SAVE` 并携带 `imageKey` |
| 固定键下已有对象 | 直接覆盖，不创建版本化键 |
| 同一赛事并发生成 | 不加领域锁，以最后完成的外部写入为准 |

## 实现提示

图片编解码和七牛对象写入属于基础设施适配；领域服务只暴露上述稳定契约。外部存储异常、编码异常与结论到应用错误的映射由调用活动完成，领域层不定义 HTTP 或应用错误码。
