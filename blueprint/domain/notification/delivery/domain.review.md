# @notification.delivery 澄清记录

## 已确认

- [Q1] 是否在后端维护微信订阅额度？
  > 不维护。后端直接尝试调用渠道，未订阅由微信返回不可触达结果。
  → 概要、C3 和边界情况

- [Q2] 微信授权是否绑定具体业务对象？
  > 不绑定。`ref_biz_id` 仅用于内容、跳转和审计，不作为发送权限或额度条件。
  → 外部引用与边界

- [Q3] 重复触达如何控制？
  > 使用稳定业务事件标识，并对 `event_id + recipient_id + channel` 建立唯一约束。不再依赖订阅额度或授权记录去重。
  → I2 和 C2

- [Q4] 未订阅等预期不可触达如何处理？
  > 记录为 `SKIPPED` 并输出信息日志，不告警、不重试、不影响业务结果。
  → 状态与边界情况

- [Q5] 如何扩展短信和邮件？
  > 通知场景保持渠道无关，内容使用语义化变量；每个渠道独立解析地址、模板和字段，并共用触达日志模型。
  → I4 和渠道扩展
