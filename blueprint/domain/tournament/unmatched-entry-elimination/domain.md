## 概要

从赛事报名与在途参与快照中判定可整组淘汰的参赛编号。

## 职责

| 范围 | 内容 |
|---|---|
| 做什么 | 按参赛编号聚合报名，依据赛事单双打类型校验成员完整性，并结合当前轮次、报名状态和在途比赛参与快照输出可淘汰与被排除编号 |
| 不做什么 | 不读取或保存赛事、报名和比赛；不改变报名状态；不推进轮次；不修复搭档、共享编号或比赛参与异常；不产生运营响应或通知 |
| 为什么不是聚合 | 判定同时跨越同一赛事的多个报名聚合和多场比赛参与快照，没有单个报名或比赛聚合能够独立承载，服务本身也不持有状态 |
| 前置校验边界 | 输出只是基于输入快照的预检结论；真正淘汰前仍须由调用活动复核赛事轮次、报名来源状态和最新在途比赛，并由报名聚合及条件持久化保证最终一致性 |

## 契约

### 输入

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `matchType` | 比赛类型 | 是 | 只接受 `SINGLE` 或 `DOUBLE`。 |
| `currentRound` | 赛事轮次 | 是 | 本次允许淘汰的唯一轮次。 |
| `entries` | 报名快照列表 | 是 | 每项包含 `entryNo`、`userId`、可选 `partnerId`、`status`、`currentRound`；空列表合法。 |
| `activeParticipants` | 在途参与快照列表 | 是 | 每项包含 `entryNo`、`userId`；只应来自指定赛事的在途比赛，空列表合法。 |

### 输出

| 字段 | 类型 | 说明 |
|---|---|---|
| `decision` | 判定 | `ACCEPTED`：输入有效并完成计算；`REJECTED_INPUT_INVALID`：必填上下文缺失或比赛类型不受支持。 |
| `candidateEntryNos` | entryNo 列表 | 可整组淘汰的参赛编号，去重并升序；拒绝时为空。 |
| `excludedEntryNos` | entryNo 列表 | 输入中存在但因结构、状态、轮次或在途占用被排除的正数参赛编号，去重并升序；拒绝时为空。 |

## 规则

R1 `matchType`、`currentRound`、`entries` 或 `activeParticipants` 任一为 null，或 `matchType` 不是 `SINGLE/DOUBLE` 时，返回 `REJECTED_INPUT_INVALID`，不返回部分计算结果。
R2 `entries` 为空时返回 `ACCEPTED`，候选与排除列表均为空；否则只对正数 `entryNo` 分组，编号缺失或非正数的记录不产生候选编号。
R3 `SINGLE` 单元必须恰好一条报名且 `userId` 非空；`DOUBLE` 单元必须恰好两条不同用户报名、两人 `partnerId` 非空且互相指向。同一编号不满足对应结构时整组排除。
R4 一个完整单元只有在全部报名的 `currentRound` 等于输入轮次，且全部 `status` 均为 `WAITING` 或 `FROZEN` 时才继续候选；任一成员不满足即整组排除。
R5 将全部在途参与快照的非空 `userId` 和正数 `entryNo` 分别建集合；完整状态候选的任一成员 userId 命中，或单元 entryNo 命中，均整组排除。
R6 同一 userId 异常出现在多个报名单元时，涉及的全部单元排除；服务不选择其中一组，也不修复输入。
R7 通过 R3 至 R6 的编号进入 `candidateEntryNos`，其余输入中存在的正数编号进入 `excludedEntryNos`；两个列表互斥、去重并按数字升序稳定输出。
R8 服务为纯计算，不修改输入列表或其中对象，不访问仓储，不生成业务编号，也不产生通知或其他副作用。

## 边界情况

- 在途参与列表为空时，只按成员结构、轮次与报名状态判定。
- `IN_MATCH` 但未出现在在途参与快照中的报名仍因状态不符被排除。
- `WAITING/FROZEN` 报名只要 userId 或 entryNo 在在途快照中命中就排除，以保护异常状态下仍在比赛的参赛者。
- 双打只有一人、超过两人、共享编号但不互为搭档、用户重复或搭档指向组外用户时均整组排除。
- 在途参与快照自身重复不影响结果；空 userId 或非正 entryNo 不进入占用索引。
- 报名记录缺少正数 entryNo 时无法形成可报告的候选或排除编号，保持不输出该记录对应编号。

## 实现提示

先按 entryNo 升序分组，并预建 userId 出现次数、在途 userId 集合和在途 entryNo 集合，可在线性扫描后稳定产出结果；使用不可变结果列表，避免调用方修改判定快照。
